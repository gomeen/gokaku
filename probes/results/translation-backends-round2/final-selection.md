# 翻译后端第二轮评测与最终选择报告

日期：2026-11-03。性质：**一次有边界的质量确认——只补评测，不接生产。** 学习模式保持关闭，`approved=false`、`0.1.1-rc.1` 与生产翻译链路不变；本轮没有修改生产 C ABI、设置或输入行为。用户盲测仍未进行，**两个后端都保持未通过**。

第一轮报告见 [../translation-backends/decision.md](../translation-backends/decision.md)。本轮的起因是该报告评审发现的评测缺口：88 条专项短文本从未进入 `all` 运行、留存集语义审阅缺失、延迟门槛读取不存在的字段导致默认通过、应保留判定全部来自测试标签。本轮逐项补齐，并新增每方向 50 条独立确认集。

## 一、结论先行

1. **small100 保持优先验证路线，quickmt 维持性能对照，两者都不合格。** 按预写的决定规则，本轮落在第 1、2 条之间：small100 的固定风险失败仍为 5 条（未清零），但其缺陷集中在词/短语级语义漂移和品牌改写，属于产品路线中「审核过的表达资源＋加固层＋品牌保护」预定处置的范围；尚无「普遍语义错误」或「必须大量拒译才能安全」的证据。
2. **quickmt 在独立确认集上进一步恶化。** 放行候选中只有 20.3%（16/79）语义合格；词级输入 88.1% 错误、时间表达 83.3% 错误。复读残片问题与第一轮一致，没有出现足以改变选择的新质量证据，速度优势（p95 43–90ms 对 134–300ms）不改变结论。
3. **评测管线已修复并加回归锁。** 专项集纳入 `all` 并有数量断言；延迟门槛读真实结果，缺数据报 `incomplete` 而非通过；候选放行／语义合格／安全回退／错误放行分开统计；失败请求保留等待与超预算记录；缺失审阅不能报完成。断言脚本 `scripts/validate-translation-eval.py` 已接入 verify fast 档（6 项断言）。
4. **用户盲测材料已就绪、未开始。** [blind-comparison.md](blind-comparison.md)（模型名盲化为 A/B，对应关系在 `blind-comparison.key.json`）覆盖 100 条确认集；盲测完成前不得打开学习模式。

## 三、质量结果

**口径**：`放行`＝输出通过加固层进入默认候选；`语义合格`＝放行且逐轮语义审阅合格（同义表达允许，评分规则见 [semantic-review-round2.json](semantic-review-round2.json)，版本 1，运行前冻结）；`错误放行`＝错误/不自然译文进入候选（**这才是关键安全指标**）；`安全回退`＝加固层回退原文，不是译文。审阅为 agent 语义审阅，非用户盲测；审阅覆盖率 360/360（small100）与 316/316（quickmt），无一缺失。

| 类型 | small100 合格/判审 | 失败率 | quickmt 合格/判审 | 失败率 |

## 四、延迟

| 后端/方向 | 短表达 p95（预算 500ms） | 短句 p95（预算 2s） | 门槛 | 超预算记录 |
| --- | ---: | ---: | --- | --- |
| small100 en→zh | 180.1ms | 281.3ms | 通过 | 1 条（确认集 `cf-e-sent-06` 565.6ms） |
| small100 zh→en | 134.4ms | 300.7ms | 通过 | 0 |
| quickmt en→zh | 83.6ms | 89.7ms | 通过 | **20 条**（最高 2,610ms：`good morning` 复读到上限） |
| quickmt zh→en | 43.4ms | 68.9ms | 通过 | **5 条**（`boss` 复读 1,418–1,809ms） |

预算门槛只取速度子集热态 p95，但本轮起**任何应译请求（成功或失败）的等待超过所在长度档预算都会记录在案**（`latency.json` `overBudget`，gate `latencyOverBudget`）：quickmt 25 条超预算记录全部是复读到 256 上限的生成；small100 仅 1 条轻度超预算。两个后端的失败请求等待时间均保留（quickmt en→zh 20 条失败请求等待 1.7–2.6s，全部进入 `failures` 统计而非成功延迟）。加固层 p95 与 IPC 开销与第一轮一致（<0.5ms），未改变排序。

资源口径不变：small100 单模型 348MB 产物覆盖双向；quickmt 每方向一份（413/410MB）。模型加载与 RSS 见 [resource.json](resource.json)。

## 五、本轮修复的评测缺口（对账）

| 第一轮缺口 | 本轮处置 |
| --- | --- |
| 88 条专项集漏测 | 纳入 `all` 默认加载；加载器断言 88/44+44，汇总断言每方向请求数齐全；缺失即报错退出 |
| 延迟门槛读不存在的 `budget` 默认通过 | 改读真实速度子集结果；成功 p95 与失败等待都不得超预算；缺数据报 `incomplete`→verdict `blocked-incomplete-latency` |
| 留存集语义审阅缺失 | 两个模型全部应译留存样例逐条审阅（173/173、153/153）；审阅文件缺失或漏条即 `blocked-pending-review` |
| 按词性把短时间表达/人名归入句子桶 | 按输入长度预先分桶（CJK 计字、拉丁计词，≤8 归短表达档） |
| 只统计「加固后可用」一个数 | 候选放行／语义合格／安全回退／错误放行四类分开统计；已知错误即使通过过滤也计 `errorReleased`，永不计合格 |
| 应保留标签冒充识别能力 | gate `preservePolicy.basis` 明示按 expectedAction 标签分组、不能证明真实识别；盲测材料中回退行显示「〔安全回退→显示原文〕」而非原始乱码 |
| 无独立确认集 | 新增 100 条（此前未使用，逐一与既有数据集去重），评分规则先冻结后运行，不用于补词或调规则 |

评测管线回归锁：`python3 scripts/validate-translation-eval.py` 六项断言——专项集确实加载（含篡改检测）、超预算数据不能报通过、缺失审阅不能报完成、已知错误即使通过过滤也不计语义合格、应保留标签不冒充识别、汇总数据量断言。已作为必需项接入 `verify.py` fast／release 档。

## 六、对照预写决定规则的裁决

| 规则 | 是否命中 | 依据 |
| --- | --- | --- |
| 1. small100 质量合格且保持性能预算 | **未命中** | 固定风险 5 条错误放行未清零；专项集失败率 35.8%、确认集 32.6% |
| 2. 仍失败，但缺陷可由通用检查或独立来源表达资源处置 | **部分命中** | 品牌改写（微软团队）可由品牌保护处置；高频词/短语义漂移（invoice、on time、辛苦了）正是「审核过的表达资源负责精确命中」的预定范围；但句子级 28.2% 失败与长尾短语无法全部由资源覆盖 |
| 3. 普遍语义错误，或必须大量拒译才能安全 | **未命中** | small100 无大规模拒译（回退仅 25/401 应译），句子级尚有 71.8% 合格；不符合「明确两套模型都不能满足」的条件 |
| 4. quickmt 出现足以改变选择的新质量证据 | **未命中** | 确认集 20.3% 合格，比第一轮更差；不因更快重评 |

**裁决：small100 保持优先验证路线、学习模式继续阻塞；下一轮按规则 2 做有边界的定向改进，不做生产接入。** quickmt 维持性能对照身份；其「句子强、短输入 debris」的画像写进记录，若未来其词级问题被上游解决，须用同一确认集复测。

## 八、不能声称

- 没有修复加固层误报，也没有接入任何保护/资源层；两模型的「错误放行」数字是**当前生产加固层**下的结果。
