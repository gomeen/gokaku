# 学习输入链路专项调研

核查日期：2026-10-30。依据 [产品方向](product.md)、[既有实测](translation-benchmark.md)、[候选核查](translation-candidates.md)。本轮只读外部资料，未下载模型、构建、跑性能或调用子代理；没有新增已实现能力。
证据标签：**[需求]** 已确认目标；**[一手]** 官方接口、上游格式或许可原文；**[推断]** 据接口推导的限制；**[建议]** 待选设计；**[待验]** 必须在真实宿主验证。来源编号见末尾，网页快照日期均为本次核查日，未保存数据包。

## 目标与分工

- **[需求]** 真实输入质量与顺畅优先；单词、短语、句子及中英双向都要覆盖。选候选后直接上屏，不强制整句预览，不自动纠正，不限制青简/Rime，也不把现有两款 MT 当完整方案。
- **[建议]** 将按键/预编辑/选词/提交与模型工作隔开；输入引擎只提供源候选和稳定标识，翻译适配器不接触宿主 client。后台设置、统计和学习记录按功能需要实现，不为它们扩张输入线程或追求高吞吐。

| 层 | 建议责任与可复用条件 | 明确边界 |
| --- | --- | --- |
| 词典 | 精确词头、词形映射、多个义项、词性和用法说明；优先检索确定性资源 | 释义未必是可直接发送的表达；有词条不等于当前义项正确 |
| 短语/表达库 | 经审阅的双语表达对、语域和适用情境；先精确匹配，再评估模板 | 模板槽位须验证词形、介词、数字和否定；模糊相似不能直接替换 |
| 本地句子模型 | 自由组合、上下文消歧、整句翻译；接收独立语向、上下文与预算 | 不让 MT 猜词典所有义项；逐词译文拼接不保证句子自然 |
| 拼写/语法 | 只检查英→中时用户自己的英语，输出独立问题范围 | 翻译正常不撤销拼写提示；拼写正常不背书译文；语法可靠后再加入 |

- **[建议]** 候选结构保存 `sourceSpan/sourceRevision/senseID/targetText/中文义项说明/词性或语域/来源版本`。例如 `bank` 的“银行/河岸”应是不同义项，不把同义释词、beam 多个改写或重复结果冒充多义覆盖；例子是设计样例，非本轮资源命中实测。
- **[建议]** 零基础用户看到目标表达和简短中文说明；候选排序可结合当前上下文与本地采用记录，但保留可选义项。一轮选词绑定候选快照：同一输入版本内，已显示的编号、候选 ID 与提交文本不被迟到结果替换，新项只追加；进入候选导航后冻结列表。源输入改变则建立新版本，旧快照不可提交；去重或重排不在用户正在选择的列表上执行。
- **[一手→推断]** CT2 `return_scores`/`score_batch` 是模型生成/打分接口，不提供经校准的“译意正确率”；`num_hypotheses` 也不是义项目录。[C] 分数、目标语检测、回译和拼写检查只能辅助，不能以阈值自动宣布译文可靠。
- **[建议]** 分开标注“资源精确匹配”“模型生成”“失败”，避免无依据的可靠徽标；数字、时间、否定、人名、网址、重复和空输出做缺陷筛查，筛查通过仍不等于语义正确。词典和表达对须人工抽检，模型按风险样例及人工双语审阅评估。

## 边界与预计算何时可用

- **[一手]** `NLTokenizer` 可按 word/sentence 返回范围，并要求同一实例在单线程或同一队列使用；它提供语言学切分，不定义输入法的提交时机。[B] `NSSpellChecker.checkSpelling` 返回疑似拼写问题范围，不是翻译质量接口。[S]
- **[建议]** 中→英先由中文引擎把双拼解析为汉字候选；未选汉字前，只对有限个源候选做低优先级预取，不能把首个汉字候选认作用户意图。记录源候选 ID、覆盖编码范围、上下文版本和语言方向。
- **[建议]** 英→中不把字母交给双拼。空格可完成单词并开始词级检查，但不必完成句子；撇号、连字符、`Dr.`、`3.14`、邮箱/URL、缩写、代码与中英混排须作为边界特例。停顿只触发可撤销预取，不自动判错、定句或上屏。
- **[建议]** 句末标点结合切分器、特例和用户提交操作判断句界；明确入口覆盖整句翻译，但不强迫每次词级输入等整句。模型 token 上限独立于字符数；超限明确拒绝或让用户选择分段，不静默截断。
- **[建议]** 后续输入可能把 `can` 改成 `can't`、改变短语边界或消歧。预取结果只有在**源文本/范围、方向、源候选、上下文、后端及配置版本全部一致**时才可复用；“缓存一致”只证明对应同一次请求，不证明翻译正确。
- **[建议]** 单词检查按完成的范围进行，句级检查等句界；编辑词中部即撤销该范围旧提示并重算。检查结果绑定源版本及 UTF-16 范围，跨 emoji/组合字符做范围校验；专名/网址等免标记策略与“未收词”分开处理。
- **[需求→建议]** `metting` 若得到可用中文，源词波浪线仍可保留；若不可用则保留输入并允许明确原文上屏，不提交猜测。中→英生成错误归工具；已上屏的词不被后来的句级结果改写，提示只出现在 Gogaku 可控制的区域。

## 异步、取消与资源预算

| 后端及证据版本 | 接口实际支持 | 不能据此承诺的内容 |
| --- | --- | --- |
| CT2 **v4.6.0** 源码，与现有实验版本一致 [C]；在线并行文档为 **4.8.4** [CP] | `asynchronous=True` 返回异步结果；`inter_threads/intra_threads/max_queued_batches` 控制执行/线程/排队。`callback` 仅 `beam_size=1`，逐生成 token 返回 True 停止该 batch 解码 | 异步不等于可随时抢占；停止解码不能打断已在执行的 encoder/算子。beam>1 不套用此回调；不能将停止后的部分文本当完整译文。队列满时即使异步提交也可能阻塞，`result()` 也会等结果 |
| ONNX Runtime **v1.23.2** C 头文件及当前 C++ 接口文档 [O1]、[O2] | `RunOptionsSetTerminate`/`SetTerminate()` 可从另一线程使关联运行以错误退出；`UnsetTerminate` 清标志后可复用。共享该 RunOptions 的在途 Run 都受影响 | 这是运行终止机制，不是每个 CPU/执行提供器算子即时抢占保证；逐步 decoder 还需在每次 Run 之间检查取消。建议每请求独立 RunOptions，旧 Run 退出前不清除其终止标志 |
| Core ML，Apple **WWDC23/10049** [M] | 官方 async prediction 配合 Swift concurrency，取消会尽力响应；推荐入口主动检查取消，并限制同时在途预测数 | 把同步预测包进 Task 不会自动成为可中断计算；同步/batch 接口不能照搬 async 的取消表现。官方示例吞吐提升不代表 Gogaku 译句延迟，更不代表 Intel 上的 Neural Engine 收益 |
| Apple Translation，官方 API 的本次快照 [A1]、[A2]、[A3] | `Configuration.invalidate()`（macOS 15+）使 `translationTask` 重跑；`TranslationSession.cancel()`（macOS 26+）**尝试**停止会话所有工作，后续请求因会话已取消而报错；批请求可用 `clientIdentifier` 对应响应 | invalidate 不是底层 CPU 已停止的证明；cancel 不是无条件即时停止，也不是取消单条请求后原会话继续使用的接口。依赖可用系统语言资源，不能当已验证的第三模型或可随应用分发的词典 |

- **[建议]** 前端串行维护状态，模型放受预算的工作队列/进程；键盘回调不等待加载、磁盘数据库、模型队列空位或结果。词典索引可预建，低优先级异步加载；学习记录异步批写，不让后台列表影响候选更新。
- **[建议]** 每个活动 composition 用“一个运行任务＋一个最新待办”作为首个待验策略；连续编辑覆盖待办，取消运行任务并标为失效；旧任务实际退出后再启动最新版本，避免假取消后任务堆积。失焦会话不继续占用推理预算，批处理不为凑满而拖延用户候选。
- **[建议]** 合并键包含会话、语向、输入范围和任务类型；翻译与拼写各自合并，不能互相覆盖。当前用户选择优先于推测候选；跨方向/模型加载的预取也要限额，避免双向多模型同时驻留挤占输入。
- **[建议]** 取消分开判定：①逻辑失效，UI/提交/记录拒绝旧结果，但旧任务可能仍消耗 CPU；②待办移除，尚未启动的计算不再入后端；③执行取消，后端退出当前计算后才释放执行名额，模型驻留内存未必随之释放。仅取消回调订阅、Swift Task 或 Future 的接收方，不足以证明③；以运行退出与资源观测验收，具体取消响应时间留作实测。
- **[建议]** 若后端没有可用计算取消，采用有界串行与丢弃结果；超预算/挂起时隔离进程可终止并重建，但有冷加载成本，不能每个按键杀进程。终止只影响计算，不清除用户预编辑；设置重启退避并允许词典路径继续使用。
- **[建议]** 明确限制源/目标 token、队列数、总线程、并发模型数、缓存字节和驻留内存；压力/热状态恶化先停预取和后台工作。预算数值、加载/卸载策略以真机为准，不能由模型体积或 CPU 核数直接推定。
- **[待验]** 分别量键盘事件→预编辑显示、候选可选、选择→宿主插入，报告冷/热与 p50/p95/p99、超时、丢键、CPU/RSS、队列及取消后剩余 CPU 时间。已有推理计时不含完整链路，本轮不给毫秒保证。

## 后端能返回结果时，如何只上屏一次

- **[一手]** IMK 为 client 的输入会话创建 controller，`client()` 指向对应 client；`deactivateServer` 提供停用通知。[I1]、[I2] AppKit `insertText(_:replacementRange:)` 插入并替换指定范围，API 没有翻译任务去重语义。[I3]
- **[建议]** 后端合同只返回 `requestID/sourceRevision/contextRevision/方向/输出/状态/资源版本`；不传 client 或插入权限。回调只发布候选，不能自行上屏、发送按键、替换宿主正文或改用户输入。
- **[建议]** 前端生成 `sessionID + focusEpoch + compositionID + revision + modeRevision`；失焦、同应用换文本框、方向/模式切换、取消及提交使相关版本失效。切回同一应用仍是新 epoch，不能只用 PID/应用名识别焦点。
- **[建议]** 用户选中**已就绪**候选时，在同一串行提交步骤核对活动 client、上述版本、源范围与固定候选 ID，消费唯一 `commitID`，只对该 client 插入一次；不先上屏中文再替换为英语，不因迟到模型结果再插入。
- **[建议]** 候选未就绪时保留预编辑并显示处理中，允许继续输入、取消或明确原文上屏；空格/回车按当前候选状态路由，不暗中选未来结果。失败、超时或断网均不自动提交原文/其他语言，不增加每次都要再次确认的流程。
- **[建议]** 状态为 `editing → committed/cancelled/invalidated`，终态拒绝重复选择和回调；两次点击、回车重复与“取消后成功回调”都不能重复提交。插入调用若故障且结果不明，不自动重试；无跨进程事务确认时不能声称崩溃恢复也有端到端 exactly-once 保证。
- **[建议]** 候选/说明面板应不抢宿主焦点，所有 UI 操作仍携带原会话标识；失焦后冻结/隐藏候选并隔离保存尚未提交输入，不能把它带入新字段或自动上屏。焦点恢复策略需宿主验证，不能只靠取消回调保证。

## 缓存与学习记录的隐私边界

- **[建议]** 翻译缓存键至少含精确源文本、源/目标语言及文字变体、边界、上下文摘要、候选义项、模型/分词器/词典版本、归一化规则、解码与提示配置。拼写缓存另含语言、检查器与自定义/忽略词表版本；缓存命中仍须通过会话版本验证。
- **[建议]** 大小写、标点、空格、数字、否定不可粗暴消除；如用归一化索引，保留原文并验证可等价复用。上下文变化使句级缓存失效；个性化排序版本单列，不能复用其他应用/私密会话的上下文。
- **[建议]** 用户文本默认仅在有字节上限和 TTL 的内存缓存，失焦/取消/隐私开关按策略清理；共享磁盘索引只存公开词典和表达资源。哈希键不是匿名化：短词可枚举，原文、译文、上下文和崩溃日志都可能泄露。
- **[需求→建议]** 学习记录只异步保存用户采用的表达、主动尝试及必要裁剪上下文，分开来源与疑似问题；预取、失败、取消、未采用候选不自动记为学习。工具生成错误不计用户错误，采用次数不等于掌握。
- **[建议]** 提供暂停、按应用排除、查看/删除与误报排除；敏感字段或无法确认安全的输入路径不记录/预取上下文，不扩展成全局键盘日志。删除须覆盖记录、关联缓存及待写队列，防止异步回写复活。
- **[建议]** 联网增强默认关闭；开启后仅发送本次明确允许的内容，不连带上传历史。性能日志仅记请求匿名 ID、长度区间、耗时和状态，不含文本；第三方适配器的日志/遥测/离线行为需另验，不能由接口可返回结果推定隐私合规。

| 场景 | 必须观察的结果 |

| 连续快速输入、退格、改词中部、候选换序，旧响应故意晚到 | 无丢键/卡主线程；同版本已显示编号/ID/文本不被替换，导航时列表冻结；输入改版使旧快照失效；最新待办有界 |
| `bank` 多义、常用表达、自由句、中英双向与小鹤源候选改变 | 展示可区别义项及来源；不倒置释义充当词典；无命中不编造，整句入口可用且不强制词级等待 |
| `can/can't`、`Dr.`、`3.14`、URL、代码、emoji、组合字符 | 不因停顿/局部标点提前判错或提交；完成词/句检查范围正确，免标记对象不因未收词而报错 |
| `metting` 可译/不可译、拼写正确但译错、生成英语错拼、数字/否定错译 | 拼写与翻译状态独立；不自动纠正；保留原输入；工具错误不记为用户错误；分数不能通行 |
| A→B 应用、同应用字段切换、点说明面板、切回 A、模式/方向切换 | B 无 A 的插入；旧 epoch 不恢复提交资格；无意外提交/丢字；面板不抢焦点 |
| 双击候选、重复回车、选择与取消竞态、回调重复/乱序、插入后 worker 崩溃 | 一次选择最多一次插入；不重试不明提交，不改已上屏内容；学习记录也去重 |
| CT2 greedy/beam>1、ORT terminate、Core ML async、Apple cancel/invalidate | 分开核对请求失效与实际工作退出；记录取消后 CPU 与新任务等待，不用隐藏旧结果冒充停止计算 |
| 冷加载、缺模型/语言资源、超长输入、队列满、内存压力、禁网、worker 无响应 | 输入与原文退路可用，无静默截断/联网/错语提交；资源有界、可恢复，按全链路分位数评估 |
| 改方向/上下文/模型版本、自定义词变更、暂停记录、删除时尚有待写任务 | 缓存不串用；不记录预取和敏感内容；删除不复活；文本不进入日志或未授权网络请求 |
