# 翻译质量独立研究（zai-coding-cn/glm-5.3）

> 本文保留子代理的原始独立意见，包含尚未证实或经复核不成立的统计、推断与建议。请结合[汇总与复核](research-translation-quality-synthesis.md)阅读，不将本页直接当作产品决定或验收证据。

性质：四模型独立研究之一，只基于本仓库源码、原始记录与本轮自建分析，未读其他模型报告。原始数据核验均由本人用 `probes/results/translation-strategy-final/requests.jsonl`（1,280 行）现场重算，非转抄报告结论。

## 一、核心新发现：瓶颈是「生成缺口」，不是「选择缺口」

决定文档称「正确候选常在 beam 内，但排序与检查未能把它选出来」（docs/translation-strategy-decision.md §七）。我对 91 条错误放行逐条做了 beam 内容核验（oracle 分析，五轮去重）：**正确译文在 beam 内的仅约 1–4 条**——清晰的只有 fin-z-096（`will land` 排第 3），边缘 2–3 条（fin-z-040 `Welcome` 第 2、fin-z-098 `receipt` 第 3、fin-e-049 `早餐` 第 2）。即 **≥95% 的错误放行是模型根本没生成出正确译文**（stapler→斯塔格勒/斯塔格尔、voucher→投票/货币、保修→Guaranteed/guaranteed），排序、评分、结构检查都无法挽回。另核验：模型路径 171 个多候选用例中 19 个前两候选仅大小写/标点不同（beam 多样性退化）；en→zh 竞争候选的反向分几乎持平（如 -5.84 vs -5.79），λ 排序天然缺乏区分度。结论：**「多候选+反向评分+结构检查」这条路对错误放行与合格覆盖都已到顶，不值得继续调参**。

其他新核验的事实：
- 「5 条正确译文被误拒」实为 4 条：fin-e-063 的 `Gogaku v1.4.2 已退出。`本身错译（is out＝发布了），两个 beam 候选都是「已退出」，即使过检查也是错误放行。
- 品牌保护不对称：`Brands.required()` 只扫描拉丁 preserve 词条（probes/translation_strategy.py:342），zh→en 句中的微信/淘宝无任何保护，`micro-scans`/`wallet` 因此通过检查（fin-z-062/069）。
- 资源层自废武功：`不客气`在 selection-seeds.txt 问候类里，但 CC-CEDICT 义项互斥（you're welcome vs impolite），被 conflictPolicy 整条丢弃（scripts/build-translation-expressions.py:8），随后模型给出「Unhosted」。而被丢弃的正确译法（订书机/防晒霜/登机牌/房东/代金券/扶梯）全部实际存在于本机 CC-CEDICT（已逐一 zgrep 验证）。
- 分类型通过率（本人按 final set 200 条重算）：短语 28%/32%、句子 53%/60%、词 55%/60%、时间 67%/73%、品牌 50%/50%（其中 5 条是可机械修复的误拒）。

## 二、瓶颈定位（分层）

**已证事实**：① 生成质量是主瓶颈（上述 oracle 分析）；② 实现层缺陷可修但只值 ~12 条（误拒 5＋品牌不对称 2＋时间模板/检查 3＋保留判定 1）；③ 标注过严是二阶因素：我逐条复核 91 条失败，可辩护的义项分歧约 8–12 条（forecast→预计、on sale→出售、cartoons→漫画等），全部改判也只到 ~54%/61%，离 95% 仍远；④ 性能不是瓶颈（短表达 p95 354ms）。

**有根据假设**：输入分布与训练分布错配是根因。small100 是 M2M-100 12B 蒸馏的 0.3B 浅解码器（3 层 decoder）模型，均匀采样面向低资源语言，评测只在句子级基准 FLORES/Tatoeba/TICO-19（HF 模型卡 https://huggingface.co/alirezamsh/small100 ）；同作者论文《What Do Compressed Multilingual MT Models Forget?》明证压缩模型在欠表征特征上显著掉分（https://aclanthology.org/2022.findings-emnlp.317）。孤立词/短语正是句子级 NMT 的分布外输入，失败类型（词义选择、MWE、搭配）与之吻合。quickmt 为 13 star 单人项目（https://github.com/quickmt/quickmt），无任何词级质量主张，当评分器信号弱有结构解释。

**未验证猜想**：用 small100 自身做反向评分（回译一致性门）能否把错误放行转为安全回退（见思路 3）。

## 三、三个新思路（排序）

1. **词/短语输入改走「审核词典多义项候选」层，模型只兜底**。机制：把反向索引的 CC-CEDICT（或扩容 expressions.tsv）的**全部审核义项**以编号候选形式进候选窗（产品已定义 Option+1–9 选编号候选，docs/product.md 三状态表），最高频义为默认，不再「义项互斥整条丢弃」；`Pipeline.lookup` 现在只用单一 target（translation_strategy.py:562），而 expressions.tsv 的「备选译法」列已存而未用。针对性：词+短语占验收集 90/200 且是重灾区；词典义项候选不是「错误猜测」，歧义交给用户选择而非强行猜义，正面化解「多义词不强行取一个义项」与「错误猜测不当可靠候选」的两难。证据：资源路径精度 8/9；本轮全部词级失败的正确译法都在本机 CC-CEDICT 中。限制：en→zh 短语（take your time 等 MWE）无许可干净的反向来源，CC-CEDICT 覆盖不了；需重定义多候选下的验收口径（产品决定，不是降门槛——每条候选仍须审核可辩护）。
2. **修复包：品牌双向对称保护＋受保护串统计排除＋时间模板变体**（决定文档 §八已列，但方向性缺口是新发现）。零推理成本，预期收回 ~12 条；单独不足以达标，属必做卫生项。
3. **small100 回译一致性门（降错误放行，不提覆盖）**：对模型候选用已驻留的 small100 做 `score_batch` 反向打分（CT2 4.6.0 已验证支持），低分即回退原文。评分 IPC 实测 26–40ms，预算内、零新增内存。限制：把错误放行变成回退会让 46%/53% 覆盖率进一步下降——只在思路 1 恢复词/短语覆盖后才有净价值；且未验证区分度。

**句子方向（60 条、53–60% 通过）无许可干净、性能合规的现成替代**：M2M100/OPUS 已实测淘汰，NLLB 系 CC-BY-NC 出局，LLM 超预算，云/API/系统翻译不合规。若坚持句子 95%，剩余路径只有对 small100/opus-mt 做许可核查后的小规模微调（MIT/CC-BY-4.0，训练一次性、推理速度不变），这是独立工作项，不在本轮验证内。

## 四、建议的一次最小验证（带停止条件）

**离线词典可恢复性试算**：不做任何推理。用本机 CC-CEDICT 反向索引对**新冻结**的一份词/短语样例（各 50 条，按 selection-seeds 类别采样、与 final set 去重）生成多义项候选，人工审核每条「是否存在可辩护义项」，统计可恢复率。停止条件：词级可恢复率 <80% 或短语级 <50% ⇒ 词典路线封板，句子模型工作项（微调/换模型）成为唯一主攻并需单独决策；达标则进入正式资源扩容＋新冻结集验收。λ/beam/编排不再调。

## 五、现实约束

500ms/Intel CPU：词典层 <1ms、small100 评分 +26–40ms、微调不改变推理成本，均合规；但不做实测不得声称任何新模型达标。跨平台：CT2 支持 Windows x64，词典/模板天然跨平台。许可：small100 MIT（tokenizer Apache-2.0）、quickmt Apache-2.0、CC-CEDICT CC BY-SA 4.0（衍生数据义务已在 manifest 声明）；用 CC BY-SA 数据微调模型权重的定性未决，需在微调立项时单独核查；云模型与 Apple/Windows 系统 API 按产品边界不可作默认。

## 六、证据局限

oracle 判读由本人逐条人工判断，边缘案例（约 5 条）可争；标注严度估算是主观复核非双盲；CC-CEDICT 可恢复性只在本轮 9 个词级失败样例上验证，非统计结论；quickmt 评分信号弱的解释基于最终集分数分布，未做受控实验；所有结论未在 Windows、真实 IMK、并发输入下验证。
