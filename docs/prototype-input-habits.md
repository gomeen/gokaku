# 输入习惯与外观原型

本原型回答一个问题：在改正式输入法代码之前，候选窗外观与比例、标点、Shift、大写字母、数字、方向键与 Ctrl 编辑键、分段选择、英文候选与词性注释、按应用默认英文、Control＋Backspace、纠错建议、全拼方案、字号与字母显示配置，以及学习模式（青简式中→英／英→中演示 + 正式功能暂停提示），是否符合用户的输入习惯。

这是可丢弃的行为与外观原型，不是正式界面或输入法实现。源文件为 [prototypes/input-habits-demo.html](../prototypes/input-habits-demo.html)（由模板生成，勿直接手改），无第三方依赖。需求依据见[产品方向](product.md)与[首阶段实施总计划](implementation-plan.md)。

## 体验方式

直接用浏览器打开 HTML。macOS 可以在项目目录运行：

```sh
open prototypes/input-habits-demo.html
```

如果浏览器工具限制访问本地文件，可以在项目目录运行预览服务（仅绑定回环地址并禁用缓存）：

```sh
python3 scripts/serve-demo.py
```

随后访问 `http://127.0.0.1:8897/prototypes/input-habits-demo.html`。命令运行期间页面才可访问。原型不依赖服务器或联网服务。

**演示前请把系统输入源切到 ABC**：否则真实按键会交给当前系统输入法，页面收不到。页面检测到组合输入时会在顶部提示。物理键不方便时可用屏显按键（左／右 Shift、Control＋Backspace、Esc）和场景引导的“下一步”。

## 页面内容

- **模拟应用区**：聊天应用／Raycast／终端／VS Code 四个模拟宿主。Raycast 与 VS Code 演示按应用默认临时英文；每个应用各自保留已上屏文字。
- **候选窗**：竖排；`Fira Code WenKai`（未安装回退系统字体）。字号可在控制条设置（12–16 号，**默认候选 14 号**；单位为 macOS 逻辑点，页面以 px 1:1 呈现——此前误用 CSS pt 导致大 4/3，已修正）：注释与拼音 −1、序号与页码 −3（明显小于候选词，对齐青简样式），行高按 46×字号/21 缩放（14 号→30.7px），行内文字按真实基线对齐并垂直居中，每页 9 个；窗口内边距 8、圆角 8、宽度钳制 [180, 440] 且随内容收缩；高亮 `#12996a` 右扩 4pt 圆角 4；页码右下仅「1/4」样式（多于一页才显示，截取说明只在状态面板）。学习演示的英文注释为琥珀色（选中行用选中色保证对比度）。浅色／深色取主题浅／深色值，阴影较淡，无动画。历史上曾因候选词 `overflow:hidden` 使 flex 改用合成基线导致错位（已修复，实测基线差 0）、页脚长说明与日期标签撑宽窗口（已移出／缩短）、CSS pt 单位偏大 4/3（已改 px）。
- **控制条**：输入方案（小鹤双拼／全拼）、输入字母显示（全拼／原码，输入区与候选窗同步）、字号、浅色／深色／跟随系统、菜单模拟（临时英文状态、学习模式置灰及原因）、候选旁英文释义与学习交互演示开关。
- **状态面板**：每次操作后的组合内容、拼音预览与光标、已暂存分段、高亮候选、页码、中英状态、刚上屏文字。
- **场景引导**：16 个场景分步演示下表行为，也可自由输入（右侧列出已预生成编码，点击可自动逐键输入）。

## 可演示的行为

| 场景 | 演示内容 |
| --- | --- |
| 中文标点 | 未组合时 `,` `.` `?` `!` `;` `:` 等转全角；`"` `'` 交替配对；前一字符是数字时 `.` `:` 保持半角（`3.14`、`10:30`） |
| 组合中标点 | `nihc?` 一次上屏“你好？”；有候选时 `,` `.`（及 Page Up／Down）翻页 |
| Shift | 输入中文（组合中）按 Shift：直接上屏输入的内容（原编码），不切换中英；未组合单击切换中英，右上角“中／英”提示 0.8 秒；左右 Shift 行为相同（2026-10-31 按用户裁决调整） |
| 大写字母 | `Cpj` 组成“C盘”（字面＋拼音候选）；单独大写字母加空格原样上屏 |
| 数字 | 1–9 选当前页；0 或超出页内数量先上屏高亮候选再输出数字 |
| 方向键 | ↑↓ 移高亮（跨页）；←→ 移拼音光标，只改显示，不重算候选 |
| 分段选择 | `wojbtm` 选“我”暂存后剩余编码继续出候选，整段选完才上屏；退格撤回最后一次选择 |
| 英文候选 | `compa`→company 等；演示按“奇数键长＝小鹤解不出完整中文”判定英文排第一，偶数键长排第二 |
| 按应用默认英文 | 切到 Raycast／VS Code 自动临时英文；手动 Shift 可覆盖；无组合时 Esc 回到该应用默认 |
| Control＋Backspace | 删除示例“已学习”候选（仅内存）；出厂词提示不能删除 |
| 输入字母显示与英文释义 | 输入区光标处同步显示输入的字母（「输入字母显示」可选原码 `nihc`／展开全拼 `ni'hao`，与候选窗同步）；候选右侧常显手写示例英文释义（词性＋译文，琥珀色，可关） |
| 学习模式 | 菜单项置灰并注明“正式翻译模型未通过质量门槛”；快捷键只提示，不切入 |
| 学习中→英（演示） | 青简式：候选注释列以琥珀色显示「词性＋对应英文」（如「1 你好 int. hello」「1 会议 n. meeting · n. conference」多义项 · 分隔），按数字／空格选中即一次上屏英文本身（不带词性），无二次确认；未配置翻译的词按普通中文上屏并提示；Control＋Shift＋J 切方向 |
| 学习英→中（演示） | 英语缓冲输入示例词或词组（`hello`、`hello world`、`good morning` 等，空格写入缓冲），候选行直接显示中文（如「1 你好」），Enter／点击上屏；`metting` 预编辑行即时标红色波浪线，候选显示纠正后的单词「meeting」＋中文意思「会议」（琥珀色），Enter 上屏「会议」；候选窗内不显示引导文字、不显示错误拼写 |
| 全拼（测试） | 输入方案切到全拼：`nihao`→你好、`jintian`→今天、`woxiangxueyingyu` 分段选择（暂存“我想”，剩余继续出候选）→ 我想学英语；与小鹤双拼可随时切换，chips 按方案列出 |
| Control＋emacs 键 | 组合中 Control＋a／e 移拼音光标到行首／行尾；Control＋b／f 光标后退／前进一格；Control＋n／p 高亮移到下一／上一候选（跨页自动翻页）；可用真实按键或「Ctrl 编辑键」场景逐步演示 |
| 输入字母显示 | 双拼之后的全拼（默认，`ni'hao`）或输入的字母原码（`nihc`；暂存态如「我jbtm」）；输入区与候选窗同步，控制条随时切换 |

## 数据来源与生成

- **预览服务**：`python3 scripts/serve-demo.py`（仅绑定回环，带 no-cache 头，默认 8897 端口），访问 `http://127.0.0.1:8897/prototypes/input-habits-demo.html`；禁缓存避免浏览器使用旧版原型。长内容（如长句候选 + 长注释）超过 440px 窗口上限时注释收缩并显示省略号，不会出现字符硬切；窗口左右内边距恒定 8px（选中行按青简规格向右扩 4px）。
- **中文候选**：`scripts/generate-input-habits-demo-data.py` 用本机已构建的 `GogakuEngine` 桥接（libime 1.1.17）生成两套数据：小鹤双拼（`T:` 前缀，正式桥接，约 40 条编码）与全拼（`Q:` 前缀，demo 专用引擎变体——由脚本从正式桥接源码派生并关闭双拼解析，输出 `.build/demo/`，不进输入法包；全拼等价编码 + hello／comp／compa／meet）。每个前缀最多 27 个（3 页），另对分段选择轨迹生成暂存后的剩余编码候选（两方案各两条）。顺序是真实出厂顺序，未开启个人调频；`mytm`→蔓越莓、`pjyn`→番禺你 等即为出厂真实首位，不是错误。
- 预生成列表之外的编码显示“此编码不在演示数据中”，不伪造候选；预编辑行仍显示真实引擎行为（libime 会给任意字母串一个尽力解析）。
- **英文候选与英文释义**：页面内少量手写数据，明确标注“示例”；不是正式 SCOWL／wordfreq 词表或 CC-CEDICT 释义。正式数据在实现阶段生成并核对许可。
- **学习交互演示**：同样为页面内手写示例（你好→hello、开会→have a meeting、我想学英语→I want to learn English；英→中 hello→你好、meeting→会议、**hello world→你好，世界、good morning→早上好** 等；问题示例 `metting`）。中→英按青简式在候选注释列显示英文，选中即一次上屏（无二次确认、无就绪态）；英→中候选行直接显示中文，Enter／点击上屏。只覆盖演示词，不代表真实翻译或词表能力；真实学习功能仍因翻译模型质量门槛关闭，菜单保持置灰。
- 生成脚本只用于 demo，不进入输入法包。重新生成：`python3 scripts/generate-input-habits-demo-data.py`（需先 `cmake --build .build/native`，并存在 `~/Library/Caches/Gogaku/libime-1.1.17/data/`）。同时产出可读的 `prototypes/input-habits-demo-data.json`。

**重新生成不是字节可复现的**：libime 对同分候选的顺序按进程不稳定（实测 351 个状态中 8 个出现同分候选换位，如 和力量／和理论、我将／我叫）。重新生成后候选集合与首位不变，但同分项顺序、页码分布可能微变；仓库内交付版 HTML 与 20 张截图对应，除非有意更新数据否则不要随意重跑后直接提交。

## 浏览器限制（页面上也注明）

- 系统输入源须先切到 ABC；检测到组合输入时页面提示。
- 浏览器文字渲染与 AppKit 略有差异，候选窗几何以 px 与 macOS 逻辑点 1:1 呈现（第五轮已修正此前误用 CSS pt 导致偏大 4/3 的问题），最终外观以正式实现的截图核对；行高按 46×字号/21 缩放（青简基础主题源码不在本机，缩放规则未经源码证实，demo 按实测行为实现），请重点对照。
- Shift 单击按“按住期间无其他按键＋按时长 <600ms”判定，左右侧按 `location` 区分；不代表真实 IMK 修饰键事件。
- 英文排序的“小鹤解不出完整中文”在演示中按奇数键长近似判定；正式实现的判定在共享核心中另行定义。
- 页内状态（含已删除的示例学习词）只在内存，刷新即清空；不写盘、不联网（内容安全策略禁止外部连接）。

## 边界

- 本页只演示外观与按键规则，不证明跨应用兼容、真实系统 Shift 事件、候选窗延迟、IMK 提交链路或焦点安全。
- 候选来自预生成数据：不代表实时引擎速度，也不含个人调频；每状态最多 3 页，超出部分仅在页码注明实际总数。
- 输入区字母显示与候选窗同步、由「输入字母显示」选项控制（原码／展开全拼）；正式实现的默认形态是光标旁浮动候选窗（预编辑不写宿主），输入区是否同显字母（青简 preedit=both 行为）已在 demo 中按常显确认。
- demo 中部分候选加标点（暂存分段＋剩余编码时按标点）可能只上屏原编码并丢掉已暂存分段；正式实现按[产品方向](product.md)规格保留暂存文字（暂存文字＋剩余原编码＋标点一次上屏），demo 不作为该细节的确认标准。
- 自定义词语（短码短语、拼音词、设置页与快速添加）未在本 demo 中演示；规格见[产品方向](product.md)「已确认的自定义词语」。
- 英文候选、英文释义、“已学习”词与学习交互演示（来源→目标翻译、拼写提示）均为手写示例；正式数据（SCOWL＋wordfreq、CC-CEDICT、用户词库）与学习链路在实现阶段生成并通过质量门槛后才会启用。学习演示的方向切换、就绪态上屏等交互细节在正式实现中仍按已批准计划执行。
- 学习模式在页面中不可用，对应正式计划中的模型质量门槛阻塞，不是本页的演示缺陷。
