# 翻译质量独立研究（deepseek / deepseek-v4-pro）

> 本文保留子代理的原始独立意见，包含尚未证实或经复核不成立的统计、推断与建议。请结合[汇总与复核](research-translation-quality-synthesis.md)阅读，不将本页直接当作产品决定或验收证据。

性质：独立研究者结论，只代表本人判断，未读其他模型报告。数据全部来自本仓库源码、原始请求记录与官方模型页；未安装/下载模型、未跑推理、未改任何生产代码或已有数据。按用户裁决，本报告以旧版 V4-Pro 署名。

## 一、结论先行

原方案「审核表达/模板优先 + small100 候选 + quickmt 反向评分 + 结构检查」未通过，**根因几乎全部在 small100 的生成能力，不在编排、打分、解码或实现**。我审查了 `probes/results/translation-strategy-final/requests.jsonl`（1280 请求）第一轮的逐条候选：**91 条错误放行（action=candidate 且标注 fail）里，88 条（96.7%）的正确译文根本不在 beam 候选中**；只有 3 条是「正确译文在 beam 内但排序没选出来」（`fin-e-015` 水管工→`水/水果`、`fin-e-049` 早餐时→`在早餐/早餐`、`fin-z-040` Welcome→`Welcome to visit/Welcome`）。反向评分只能重排已存在的候选、结构检查只能否决——当 beam 里没有正确候选时，两者都无从发力。因此「多候选＋反向评分没把正确候选择出来」的报告归因不准确：不是选择失败，是生成失败。

## 二、瓶颈定位（按证据强度）

**已证事实：**

1. **模型容量是主瓶颈。** small100 是 SMaLL-100 蒸馏模型，**333M 参数、100+ 语言**（官方模型卡 alirezamsh/small100 及 EMNLP 2022 论文 https://aclanthology.org/2022.emnlp-main.571），每语言容量极薄。88/91 错误放行的正确译文不在 beam，是其直接的量化证据。
2. **失败集中在日常高频词/短语。** 验收集 `validation/translation-final-set.json` 中 width=1 的孤立词 39 条、width 2–4 的短短语约 80 条，日常词汇合计约 70%。逐条审阅（`acceptance.json` failures）：`stapler→斯塔格勒`（音译编造）、`sunscreen→太阳镜`、`voucher→投票`、`外卖→External sales`、`报销→Replacement`、`不客气→Unhosted`、`怎么办→How to`——全是词典能一击命中的日常表达，small100 系统性失败。
3. **结构检查误拒是真实但次要的缺陷。** 品牌/版本号串未从脚本校验的「语言主导」与长度比率统计排除（`translation_strategy.py` 中 `Structure.check` 调用 `gc_translate_script_check`/`gc_translate_length_check` 前未剔除受保护串跨度），导致 4 条正确译文被拒（`fin-e-061`「在GitHub上打开 PR。」、`fin-e-062`「更新到 macOS 15.2。」、`fin-e-067`「使用 WeChat 登录。」、`fin-z-065`「Gogaku is updated to v1.4.2.」）。修掉也只回收约 4/200，与 95% 目标无关。
4. **反向评分不是方向中立改进。** zh→en 已按预先规定 λ=0 禁用（λ>0 会把「他不在上海，在北京」选成丢对比关系的译文），见 `run.json` `lambdas`。
5. **报告口径不严谨处（用户已指出，我核实确认）。** ① `forecast→预计`、`on sale→出售` 被判 fail 过严（裸词 forecast 在商务语境更常译「预测/预计」）；② 所谓「5 条正确误拒」中 `fin-e-063`（`Gogaku v1.4.2 is out.`→「已退出」）本身是**错译**（is out 应为「发布」），被拒理由虽错（script 误判）但结果不冤，因此真正「正确却被误拒」是 4 条，不是 5 条。

**有根据假设：**

- 两轮「70.8% vs 46%/53%」不可比。第二轮语义合格 255/385 的分母是「放行候选」且集是 risk+holdout+short+confirm 四套；本轮 46%/53% 分母是新冻结 final 集（日常词汇更重、难度更高）。差值是**测试集构成差异＋模型容量**，不是「策略让它退步了」。
- 修复结构检查误拒 + 纠正过严标注后，真实覆盖率约在 50–55%，距离 95% 仍有结构性鸿沟，结论不变。

**未验证猜想：**

- 换大模型（MADLAD-400 3B-MT）能否在 Intel CPU 上满足 500ms/2s 预算——只能实测，不能外推。research-translation-model-unblock.md 已推测「300ms–1.5s 贴预算」。

## 三、降低错误放行 vs 提高合格覆盖（必须分开）

- **降低错误放行**（安全）：结构检查 + 反向评分 + 回退原文是**有效的安全层**——91 条错误虽过结构检查，但乱码/URL/版本/错拼/超长等应保留输入被正确挡下（24 探针 19 保留）。这条路可以继续加固（修品牌/版本统计污染、补 `o'clock`/`a.m`/英文数词模板、`qwerty` 键盘串规则），**但它是「更安全地少放行」，不是「更正确」**。
- **提高合格覆盖**（质量）：只有两条路——换更强的生成模型，或把词/短语层搬到不依赖模型的地方。编排层对覆盖率贡献的上界就是 beam 里已有的正确候选，实测仅 3/91，接近零。

## 四、新思路（最多 3，已排序）

1. **词/短语层走大规模审核词典，模型只兜底句子（最高价值）。** 验收集约 70% 是日常词/短短语，而资源路径精度已证 89%、模板 100%（`acceptance.json`）。把 expressions.tsv 从 180/300 条手工小表扩为大规模审核双语词典（CC-CEDICT 12.5 万条 + 高频短语表），词/短语精确命中即可近 100% 精度，模型只剩约 30% 句子负担。**局限**：多义词消歧（CC-CEDICT 义项多）会重新引入 forecast→预计 这类错误，故必须保留「义项不唯一整条不进」原则，覆盖上限受多义词占比约束；需要一份新的冻结验收集复验，不能用本轮集调参。
2. **换单模型为 MADLAD-400 3B-MT（Apache-2.0，CT2 原生）兜底句子层。** 3B T5、450+ 语言、1T token，是唯一许可干净且 CT2 原生支持的强候选（官方 HF google/madlad400-3b-mt；CT2 issue #1560 已证可转）。**局限**：比 small100 大 9 倍，CPU 延迟大概率贴/超预算，必须先实测。
3. **方向分治。** zh→en 与 en→zh 失败类型不对称（en→zh 词级漂移、zh→en 短语/义项漂移）。zh→en 用 Mozilla zh→en 59M（MPL-2.0，官方 chrF++ 55.4）或 opus-mt_tiny_zho-eng（Apache-2.0，约 20M），en→zh 另解。**局限**：Mozilla en→zh 已排除（SSRU 解码器 CT2 不支持 + 训练数据缺陷自曝），方向分治引入两套模型/分词，增加双端一致性与维护成本。

**现路线（small100+反向评分+结构检查）不值得继续投入**：88/91 错误放行无正确候选在 beam，任何编排改进都不能修复生成能力，天花板约 50%。

## 五、唯一最小验证与停止条件

**一次运行：MADLAD-400 3B-MT 延迟实测 + 冻结集词/短语子集语义抽查**（复用现有 worker 协议，固定 INT8、2 线程、greedy/beam 与现在一致，不改参数矩阵）。

停止条件（任一不满足即终止该路线，不进入下一轮选型）：
1. Intel i9-9880H 热态短表达 p95 ≤ 500ms 且短句 ≤ 2000ms（复用现有速度子集口径）；
2. 冻结 final 集的词/短语子集（不用于调参）语义合格率显著高于 small100 的 48.9%。

若延迟不达标 → 放弃换大模型，转入思路 1（词典分层）＋思路 3（方向分治）组合，同样先建新冻结集再评。**这是唯一的模型级出口，不再扩模型名单。**

## 六、500ms / 离线 / 跨平台 / 许可的现实约束

- small100 实测短表达 p95 353.8ms（`acceptance.json`），证明 encoder-decoder 短输入在此硬件可达预算；MADLAD 3B 是 T5 结构约 9 倍参数，**无测量不得声称达标**。
- 云模型（GPT/DeepL 等）违反「核心离线」硬约束，不能作为默认；Apple Translation 已于 2026-11-02 裁决退出正式链路，macOS/Windows 系统 API 不能当合规替代。
- CT2 官方支持 macOS dylib + Windows MSVC，两端同权重同参数可行；但不同 CPU 后端不保证逐字一致，替换后两端需分别跑同一验收集审阅差异。
- 许可：MADLAD Apache-2.0（权重）/ 数据 CC-BY-4.0、Mozilla 59M MPL-2.0、opus-mt_tiny Apache-2.0、small100 MIT、CC-CEDICT CC BY-SA 4.0（衍生须声明修改）。均宽松；但项目许可未定，CC-BY 署名义务须在分发前逐条落实。
