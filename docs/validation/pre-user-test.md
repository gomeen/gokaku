### 验收工具两处判定缺口（已修＋合成回归）

1. **插字次数核算**：旧驱动把每轮笼统算成一次提交；逗号／句号后键在无组合状态走标点表，每轮应为「正文确认＋标点插入」两次插字。现按确认事件与后键分别计算（状态计数器逐轮恰好相等，漏字偏小、重复偏大都不通过），并在样本流里逐轮按事件归位：插字只准落在确认事件（Shift 为释放事件）与标点后键事件上，每次插字必须回调内隐藏。合成回归（`--self-test`）验证：正确的两次插字不误报，漏字／重复插字／插错事件／隐藏失败仍会失败。
2. **光标可观测性**：Terminal 不再用字符串长度冒充实测光标（旧判定永远不可能失败）；无组合时用行为学核对——数字 7 透传必须落在已确认正文之后，行编辑宿主再 Ctrl＋A 移到行首插 8 核对全文，并把光标移回行尾避免污染下一轮重置。PTY 连选区语义都没有，明确记「未验证」并计数上报；浏览器用 AX 焦点选区，读不到时同样记未验证。候选窗拼音光标另用真实窗口数值插点核对（见下）。

### 短测发现的确定性问题（已修，均有前后证据）

1. **拼音光标在宿主 marked text 里丢失（产品级缺陷）**：纯 NSString 的 `setMarkedText` 会被宿主端 IMK 机制把选区改写成 `(0, len)`，宿主里整个预编辑被选中、光标不动；改用 `NSAttributedString`＋`NSNotFound` 替换范围后光标保留（与 Squirrel 同源结论；`replacementRange (0,0)` 会被当成绝对位置 0 在正文前插字，已实测排除）。系统拼音对照确认宿主本身支持插点内选区。
2. **验收探针的 reset 直接 `unmarkText` 会把宿主 marked text 撤掉而核心组合仍在**，下一轮字母拼进残留组合（「你你好／出你好」残留路径，也是旧 Chrome 矩阵残留症状的成因之一）。探针 reset 改为先发真实 Esc（输入法同步取消）再清空。
3. **LaunchServices 里 76 个旧备份包导致输入法随机启动旧二进制**：同机多次安装的备份仍在注册表里，不同轮次跑的是不同代码。已清理只保留一份，并在安装后重新注册；此风险已记入项目记忆。
4. 驱动侧：旧 socket 文件被当作可用（输入法重启期间 connection refused）、引擎就绪前的按键透传污染轮次、探针无 Edit 菜单导致 ⌘A 无效、TextEdit 未保存文档不能用 AppleScript 命名（改为先建文件再 open）、zsh 用户钩子改写终端标题（专属标签改用 `zsh -f`）、Esc 透传会破坏后续 Ctrl＋U（终端重置改 Esc＋Ctrl＋C）。均已有对应修复。

结论：

- **核心执行（~3.0–3.5ms）与队列等待（~5µs）全程恒定**，不随正文长度变化；宿主事实读取也恒定（~2ms）。长度效应全部落在同步 marked 写入与提交：IME 侧写入耗时≈探针侧实测的 `setMarkedText` 耗时，即**输入法侧没有额外开销，成本就是宿主文本系统调用本身**。
- **同 4500 字，单段 10.92ms vs 分段 4.06ms**：成本随「被编辑行的行长度」增长，不是文档总量——正式测量的连续追加场景（正文不断追加无换行，至 4,237 字单行）恰好是最坏情况。
- **撤销记录无影响**（14.97 vs 14.62）；**拼写纠正＋5.6ms**（宿主侧）；**展开全拼 vs 原码无差异**（预编辑长度不是因素）。
- 关闭输入区字母后 4500 字回调 p95 仍 8.00ms（提交 insertText 同样付行布局成本，p95 6.58ms）；空文档＋关闭字母是最接近门槛的场景（p95 5.55ms，**仍高于 5ms 门槛**，不构成达标场景）。更正：本文早版曾误写为“低于 5ms”。

**停止条件触发**：对 4000+ 字单行文档，必要的同步宿主调用（marked 写入 p95≈10.9ms，单次提交≈6.1ms）本身已超过 5ms 预算；这不是输入法侧冗余，无法在保持逐键同步宿主写入的前提下用局部优化消除。按计划输出确定瓶颈并继续阻塞试用；后续方案若要达标，需要在「异步/合并宿主写入（改变可见反馈语义）」或「长单行场景豁免」之间做明确取舍，不在本轮自行变更。

本轮实施的局部优化：提交事件同一写入阶段的重复焦点读取合并（applyNormal 复用写入前核对，少一次跨进程读取）；L0/L4500 前后对照 p95 无可测差异（宿主布局主导），保留是因为结构性减少一次跨进程调用且行为等价，见 attribution-after/。未动 libime 参数与候选质量。

## 本轮实现

1. 空闲状态每键使用当前光标定位，不比较上次组合的旧锚点；组合中保留应用、进程、锚点与宿主 marked range 的核对。光标矩形失效仅影响面板定位，不使客户端读取整体失败。
2. 提交、挂起与提前返回同步隐藏候选内容并递增渲染代次；面板排版延后至下一次主线程循环，仅执行最新代次。启动时预建面板，隐藏采用透明和移出屏幕。
3. 平台使用核心报告的 UTF-8 光标偏移，转换为 UTF-16 后同时传给候选窗和宿主字母选区；分色前缀独立处理。宿主 marked 写入后回读其实际位置重锚，覆盖需要第二个后键才暴露的旧选区问题。
4. 移除记录按键、字符与组合内容的临时日志，删除旧 `/tmp` 日志与开关；打包检查扫描源码及产物。验收构建的私有 socket 只返回计数、耗时与可见性，需 0700 目录和 0600 开关，正式构建不包含该服务。
5. 核心每个事件复用候选合并结果，仅物化当前页与下一页最多 18 项，快照只复制当前页；英文候选改用索引，释义及学习词按需查询。没有下调解码质量参数。
6. 复查发现的草稿问题一并修复：保存原编码而非展开拼音；已产生但未能发出的提交保存为字面文本；恢复时统一核心字段身份、更新共享会话记录并显示最终快照。默认英文应用恢复中文草稿会显式回到中文。组合中 Shift 单击的释放条件和右 Shift 键码已修正。
7. 修复部分候选后按标点仍保留组合、带暂存前缀时删除学习词误用展示文本的问题。修前新增核心回归 7 项失败，修后 257 项断言全部通过。构建默认改用 Release；每个组合首次 marked 写入后重锚，后续保留写入前焦点复核，减少重复读取。

按约定在继续优化后仍未达到体感门槛，**停止交付试用**。最终真实宿主连续两轮、十万序列插桩及内存／两小时稳定性／冷启动保留为未完成，不以历史证据补齐。前台和输入源已恢复为原环境，验收开关已删除、诊断进程及 socket 已停止；旧字符日志与旧开关均不存在，见[清理记录](final-mac/cleanup.json)。
