# 本轮独立复查处置

MiniMax 进行了平台焦点／渲染、核心缓存／快照以及修复后的焦点复核。复查均为只读静态审查；下面把推演、实际反例与修复验证分开记录。

| 问题 | 处置及证据 |
| --- | --- |
| 核心已产出提交，但插字前目标失效时可能丢失 | `applyNormal` 保存字面文本草稿，原编码单独保留；不把中文提交当小鹤重放。草稿使用实际应用／模式／方向。静态复核确认在位，真实失焦路径仍待宿主矩阵 |
| 提交后首次选区可能为旧值，第二字母才被误判换框 | 写 marked text 后按宿主实际 marked range 重锚；首键驱动额外续输第二字母。静态复核确认，最终宿主矩阵待跑 |
| 草稿保存的是展开拼音而非原编码 | Swift 封装 `gc_normal_copy_raw`，`CompositionView.raw` 保存原编码；桥接回归断言 nihc 与 ni'hao 不混用 |
| 恢复草稿字段身份不一致、无可见快照 | 使用同一核心字段，更新 `EngineHub.lastAppField`，同步重放后应用最后快照；MiniMax 复核串行队列保序 |
| 部署件仍带旧日志代码 | 最终源码重新构建、安装并扫描产物；见 bundle-installed.json 与 identity.json |
| 部分覆盖／英文等候选后按标点未清组合 | 已实测复现：nihc→左→左→!。修前组合、候选、marked 与原编码均残留。提交标点后统一清上下文并使合并缓存失效；增加确定性回归和 fuzz 的“有提交即无组合／候选／原编码”不变量 |
| 带暂存前缀时删除学习词使用了展示文本作键 | 已实测复现：学习你好，再暂存我后删除我你好。修前提示删除“我你好”，标记与持久化均未删除。改用裸词你好删除，回归核对当前标记及重载不复活。出厂候选仍可保留，不把“去除学习标记”误写成“删除出厂词” |
| 默认英文应用恢复中文草稿被直输吞掉 | `NormalEngine.restoreRawInput` 显式回中文后按同一字段重放；Swift 回归覆盖默认英文、临时英文及恢复后继续输入。菜单的真实宿主恢复仍待实测 |
| 关闭输入区字母后同应用同偏移字段混淆 | 原点击反例遗漏了 mouseDown／commitComposition／deactivate 均会挂起的路径；但其有效性依赖宿主实际转发 IMK 事件。记录为未验证能力，不能据静态代码宣称跨字段安全通过 |
