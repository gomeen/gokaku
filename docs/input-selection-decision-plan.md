# 收敛选型：必要测试与停止条件

本轮目标是作出首阶段技术选型，不是穷举所有引擎。依据产品要求：实际输入性能优先，同时满足小鹤、候选质量、提交正确性与离线条件。复用已有105,600次按键实验及翻译结果，不重新进行全参数调优。

## 冻结范围

1. 新增80条独立手写中文保留样例，在查看输出前冻结目标和小鹤按键，五套已装配配置只跑一次质量，不按结果改答案。
2. 只对最有竞争力的雾凇 R1、libime I0 和青简 Q0 补打字节奏测试；青简保留是因为已有较低中位延迟，不能仅凭首轮长尾先淘汰。原样使用已有参数和数据。
3. 同一个自编 AppKit 文本客户端适配器承接预编辑、候选及提交，验证原生 NSTextView 的实际文本结果。它不注册系统输入源，不冒充 IMK 激活、其他应用宿主或屏幕可见测试。自建 AppKit 的取舍依据是产品所需可控候选与英语诊断能力，不声称其速度击败未测框架。
4. 模型进程驻留但空闲为基线，再启动已有最快的 OPUS CT2 INT8 双向真实推理，2线程；按键以固定100ms间隔投递（每秒10键的合成节奏，不声称代表所有用户）。比较核心时间、请求往返、排队迟到、AppKit离屏绘制返回时间。使用3轮、配置与负载顺序交错；报告样本数量和热状态，不假称正常频率。该负载用于竞争测试，不代表OPUS质量被接受。
5. 核对现有组件的具体许可材料和阻塞。复用已证实的翻译质量失败，不通过重复生成或增大beam掩盖失败，不为凑齐默认模型继续下载新模型。

## 决策与停止条件

- 先比较硬性功能、完整提交和许可可行性，再看独立质量集以及有负载时的p95/p99、资源；不把微小分差或单次最大值当作普遍胜负，不预先捏造质量—速度加权总分。
- 在已测合格候选中明确选择一个首阶段默认中文组合，并给出其余不选原因；未测路线无已知胜出证据或有未解决数据授权条件时不继续装配，不称其性能失败。
- 明确前端实现路线、推理runtime与模型采用/拒绝结论。没有合格自由句模型则明确该产品要求尚未满足，不能把“选定工程路线”包装为“完整产品可交付”。
- 无需把未来所有宿主兼容性回归和发布审计做完才作工程选择；但在未注册输入源、未做外部应用宿主测试时，不声称已完成输入法验收。安装/启用输入源仍需事先告知。
- 输出一份最终技术选择文档，产品状态同步；除非这些测试出现具体阻塞，不再追加无界候选或同类基准。
