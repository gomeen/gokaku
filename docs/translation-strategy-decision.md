# 翻译组合策略决定（2026-11-04）

本页记录一次有边界实验的**策略决定**：把「审核表达／模板优先 + small100 生成候选 + quickmt 反向评分 + 结构检查」固定成一条路线跑通，并在冻结策略后做一次验收。结论是**未通过**——95% 合格覆盖率门槛没有达到，学习模式继续关闭。验收证据见[首轮验收报告](../probes/results/translation-strategy-final/report.md)。

本页不重新比较模型名单、不重跑单模型基线、不扩大参数矩阵；单模型选择仍是 [第二轮评测](../probes/results/translation-backends-round2/final-selection.md) 的结论（small100 优先验证、quickmt 维持对照）。

## 一、已有事实（本轮开始前已核实）

- **单模型质量不足。** 第二轮放行候选中 small100 语义合格 255/385（70.8%）、quickmt 145/385（45.9%）；即使事后知道答案、从两者里挑正确结果也只覆盖 294/385。这是当前输出的上限，不是改进后的上限。
- **解码参数不一致。** small100 官方配置使用 beam=5，此前统一评测用 beam=1。候选生成需要一次解码，不能只过滤第一候选。
- **分数不等于正确性。** 原始分数与正确性相关，但明显错译也能高分（`我对花生过敏`→`I am allergic to flower`）。分数不得解释为正确概率。
- **反向评分的接口可用。** 本机 CTranslate2 4.6.0 的 `score_batch` 支持对已知源／目标文本评分；`translate_batch` 支持 `num_hypotheses` 与 `return_end_token`，可以判断候选是否正常结束。探针实测：`good morning` 的三个候选归一化分数 −0.64／−1.73／−3.22，`invoice`→发票 −1.90 优于 →账单 −3.52。
- **资源许可明确。** CC-CEDICT dump（2026-11-02，125,356 条，CC BY-SA 4.0）在本机缓存可用；jieba 词频（MIT）与既有英文词频表可作选词依据。**Tatoeba 本机无副本，本轮未引入**：没有可用句对文件，也就没有可核对的许可与署名，按「许可不明或未经审核的条目不发布」处理。
- **加固层 v1 的边界已知。** 单字级繁简、时间检查按词元近似、句首大写词不作保护候选、URL 不计入长度——这些在第二轮记录为「第一片局限」。

## 二、本轮方案假设（可能错，必须实测）

| 假设 | 结果 |
| --- | --- |
| 反向评分能把「正向高分但语义错」的候选排到后面 | **方向不一致**：en→zh 有效（关键错误 3→2），zh→en 反而把丢失对比关系的候选排到第一（3→4） |
| 审核表达资源能覆盖日常短输入的主要缺口 | **部分**：最终集只命中 9/200（4.5%），精度 8/9；句子与多数短语覆盖不到 |
| 双向时间／日期模板能覆盖独立钟点与区间 | **基本成立但边界窄**：命中 6 条、合格 5 条（1 条被时间检查误拒）；`at 7:30 a.m.`（尾点被归一化）、`half past nine`（英文数词）不在模板范围 |
| 多候选生成（beam 2/5）能提高可提交率 | **未验证成功**：正确候选常在 beam 内，但排序与检查未能把它选出来；错误放行 91 条 |
| 加固层能挡住大部分错误 | **不成立**：放行精度仅 49.5%／54.6%，且反向出现 5 条正确译文被误拒（品牌／版本号污染语言与长度统计） |

## 三、固定路线（已实现）

```
完整输入 → 运行时保留判定（错拼/未知/URL/版本/超长）
        → 品牌规范映射（完整输入）
        → 审核表达资源（完整输入精确命中）
        → 双向时间/日期模板（完整输入覆盖）
        → small100 候选生成（短表达 beam=2/2 候选；短句 beam=5/3 候选）
        → 结构检查（重复/时间/脚本/长度/品牌保留；未正常结束即失去资格）
        → quickmt 反向评分（候选→原文；λ=0 表示该方向禁用）
        → 排序取第一条就绪候选；全部被否决则保留原文
```

- **候选生成只做一次。** 达到解码上限而未正常结束的候选直接失去提交资格，不裁尾冒充完整译文；完全重复的候选合并；每个输入只生成一次，失败后不轮流换参数。
- **反向评分只排序，不生成。** 中→英用 `quickmt-en-zh` 以候选英语为源、原中文为目标；英→中用 `quickmt-zh-en` 反之。分数是长度归一化对数概率；λ 只影响排序。
- **结构检查只否决它确实识别的矛盾。** 检查通过不标记「语义已保证」；不使用占位符替换、强制前缀或任意删尾修补译文。
- **时间与数字关系。** 加固层 v2 把时间检查改为逐条「数值＋时段」对比：合法区间（上午九点到下午四点）不再误判；英文动词 `am` 不再触发时段检查；未被时间表达解释的数字必须保留且顺序不变。
- **合法叠词不再当复读。** 看看／试试／哈哈／多多少少／一个一个／一天一天放行；「早上好 好 好」「参加会议 会议」仍然拦。
- **品牌。** 29 个无歧义专名进入保留表（含句首，C++ 扫描与审阅表双向一致），6 个有常用汉语名的走规范映射。`slack`／`zoom`／`notion`／`word`／`excel`／`windows`／`apple` 这类同时是普通词的串不进保留表。

## 四、审核资源与选词

- **来源**：CC-CEDICT 义项。每行保留方向、源表达、译入表达、义项组数、词头、拼音、审核状态；义项数超过 3 组、或同一词头存在互不一致义项的条目**整条不进资源**（不把某一个义项当成唯一正确答案）。拼音首字母大写的专名条目一律不进（苹果公司的 Apple 不会覆盖水果）。
- **选词**：`resources/translation/selection-seeds.txt` 的类别清单（问候／时间／交通／饮食／天气／工作／购物／健康／生活／沟通／教育／情感）＋ jieba 词频，**不从任何评测集的失败样例补答案**。
- **复核**：整表人工逐条复核，103 条否决性改写记入 `review-log.tsv`（例：`need`→需要、`hot`→热、`后悔`…），其中 40 条改写目标不属于该词头的词典译法，属人工判断，已在清单计数里单列。
- **规模**：en→zh 180 条、zh→en 300 条。首片刻意保守：多义、俚语、专名、长短语一律不进。

## 五、λ 选择与封板

开发数据一次性采集（420 条：风险 32＋留存 200＋专项 88＋确认 100，λ=0 也采集反向分数），在 72 条有语义标注的用例上离线比较 λ ∈ {0, 0.25, 0.5, 1}：

| 方向 | λ=0 | λ=0.25 | λ=0.5 | λ=1 | 选择 |
| --- | --- | --- | --- | --- | --- |
| en→zh | 风险错 3／覆盖 22/33 | 风险错 2／覆盖 23/33 | 同左 | 同左 | **0.25** |
| zh→en | 风险错 3／覆盖 21/35 | 风险错 4／覆盖 21/35 | 同左 | 同左 | **0**（预先规定的退出路径） |

选择顺序在运行前固定：关键风险错误更少 → 合格覆盖更高 → λ 更小。封板记录（λ、资源、模板、品牌表、编排代码、worker 与 dylib 哈希）在 `probes/results/translation-strategy-freeze.json`；封板后没有根据最终验收输出改 λ、补词或改规则。

## 六、实测结论

1. **门槛未过。** en→zh 46.0%、zh→en 53.0%（门槛 95%）；错误放行 47／44 条；回退 7／3 条。
2. **分路径**：资源 8/9 合格、模板 5/6 合格、模型路径 86/176（48.9%）。资源与模板的精度足以交付，但合计只覆盖 15/200——**95% 门槛无法靠资源达到**。
3. **性能达标**：短表达 p95 353.8ms（预算 500）、短句 p95 527.7ms（预算 2000），超预算 2 条全在短表达档；结构检查 <1ms。
4. **固定风险集仍不达标**：5 条意义破坏进入候选，其中 1 条是错拼输入被当成正常输入翻译。
5. **缺陷清单**（详见验收报告 §六）：受保护串污染语言／长度统计（5 条正确译文被误拒）、区间第二个时间点渲染成 `o'clock` 被拒、`a.m.` 尾点与英文数词不在模板范围、保留判定把 `qwerty` 当常用词。

## 七、决定与停止规则

- **未通过 → 学习模式继续关闭，不接生产翻译辅助进程。** 生产 C ABI、设置页与输入行为不变；本轮全部证据来自隔离辅助进程。
- **不自动进入下一轮。** 本任务到此结束：不自动补词、不调 λ、不换解码参数、不重跑模型矩阵。是否继续投入需要单独决定。
- **封板后有两处附加改动**（都不改变验收决策）：① 为满足「审阅品牌表与共享加固层扫描一致」的断言，在 C++ 品牌表补了 `docker` 一个词条（不出现在任何验收集与探针源文中，已核对；76 项加固断言与 ctest 复跑通过）；② 把驱动里 `--beam-short`／`--beam-long` 真正接进编排层，默认值与验收时实际使用的 2/2、5/3 完全相同。用同一封板文件重跑前必须先重新封板。
- **根因在候选质量，不在编排。** 编排层按设计工作（资源/模板/评分/检查都有可复现证据）；模型路径合格率 48.9% 与第二轮单模型 70.8% 的差距说明：多候选＋反向评分没有把正确候选择出来，而结构检查的放行尺度也不足以兜住错误。微调或更换 small100 属于**另一个需要明确决定的工作项**，不在本轮范围。

## 八、下一轮的候选工作（需先决定，未开始）

1. 修受保护串统计：脚本校验与长度比率排除品牌／版本号跨度（与 URL 同一处理），消除 5 条误拒。
2. 修时间模板与检查的变体：`a.m`／`p.m` 无尾点、英文数词、区间时段继承、`o'clock` 识别。
3. 保留判定补键盘串／无元音词规则；错拼输入不得进入模型路径（风险集 `metting` 案例）。
4. 资源扩容必须先解决「多义词不强行取一个义项」与「覆盖 vs 精度」的取舍，并换一份新的冻结验收集复验，不能用本轮的验收集调参。
5. 若仍以 95% 为目标，需要正面回答：在 beam 内正确候选存在但排序无法选出时，是否接受「更少放行、更安全回退」的路线（覆盖下降），还是必须改进模型本身。

## 九、不能声称

- 用户盲测未进行；46%/53% 是 agent 逐条语义审阅，规则冻结在验收集里。
- 未验证 Windows、真实 IMK 候选窗、宿主插字、取消／焦点／迟到结果。
- 未证明 quickmt 反向评分在其他领域或长句上同样有效；zh→en 已禁用评分调用。
- 资源精度 89% 不等于整体质量；覆盖 4.5%。
- 「加固通过」不代表语义正确：本轮 91 条错误译文全部通过了结构检查。
