# 中文输入引擎首轮实验方案

本轮承接[整体选型](input-method-research.md)与[中文专项](research-ime-engines.md)。目标是在当前 Intel Mac 实际比较小鹤候选与逐键核心性能。本方案先于正式测试写定；日期、源码和实际可运行配置由结果 manifest 固定。

## 范围

- 仅隔离中文解码，不安装、注册、切换输入法，不读取个人词库/输入日志，不连接真实宿主，不把核心速度称为屏幕响应。
- 外部源码、词库、模型与依赖产物只放 `/tmp/gogaku-ime-benchmark/`。仓库保存自编探针、合成样例、运行 manifest 和结果。
- 首轮比较 Qingjian Q0 静态/统计、Rime R0 官方小鹤、R1 雾凇小鹤、R2 万象标准版小鹤、libime I0 出厂数据。它们不是候选范围上限；其他中文解码库和技术栈按相同小鹤、质量、提交正确性门槛加入，实际输入性能第一。部署成功和许可材料可核查才加入；缺失配置明确列未完成，不能退化为另一配置而沿用原名。
- 先产品数据赛道；本轮不把不同数据下差异归因于纯解码器。受控同词表赛道另行实施，不能把本轮称为完整公平排名。
- 禁用真实翻译、云能力、神经重排和用户学习；每个配置使用独立的新用户目录。生产方案若必须改选项或移除功能，逐项披露，不能称为完整默认体验。

## 固定输入与质量规则

`probes/input-engine-cases.json` 使用手写场景与明确读音生成小鹤按键，覆盖日常、工作、技术、新词和歧义。使用同一份按键，不从候选词库抽题。它是小规模回归/探索集，不是普遍质量评测或真实用户输入分布。生成器映射需与各引擎内置小鹤及已知示例交叉核对。

- Top-1：最终输入状态的第一候选是否等于允许目标之一。
- Top-10：实际枚举的前十候选是否含允许目标。候选精确出现与完整输入可提交分别记录；前缀候选不能当作整句完成。
- 目标完成：另行查询相同输入，显式选择匹配项，检查最终 commit、剩余原编码和 composition。没有匹配或一次选择只完成前缀，不能称为完成目标。
- 歧义无上下文时允许多个合理答案，目标别名在运行前冻结；不看结果再放宽答案。
- 本轮可记录目标所在索引与选择代价下界，不用它冒充实际用户按键数；局部选词、翻页、错误修订与学习收益另设轨迹实验。
- 保留每条最终候选和提交状态供人工核查，不用输出非空当质量成功。

## 共同 worker 协议

每个独立进程 stdin/stdout 使用 JSON Lines，UTF-8；日志写 stderr。第一行是 `{"ready":true,"engine":"...","version":"...","load_ms":0,"config":{...}}`。load_ms 明确起止边界，父进程另量启动到 ready。

请求操作：

```json
{"op":"reset"}
{"op":"key","key":110}
{"op":"select","index":0}
{"op":"peek"}
{"op":"quit"}
```

`key` 为 ASCII 码，8=Backspace、27=Escape、32=Space；其余本轮主要为小写字母和拼音分隔符。无效操作返回 ok=false，不能静默当成功。reset 清本次 composition、残留commit和暂存文本，不学习。质量pass额外传 `fresh=true`：Rime重新建立session清除commit_history；其他引擎清上下文链。正式计时pass不提交，reset只重置composition；静态数据不重新从磁盘部署。

除 ready/quit 外响应结构如下，字段完整，整数以纳秒计：

```json
{"ok":true,"handled":true,"preedit":"ni hao","raw_input":"nihc","candidates":["你好"],"commit":"","composing":true,"process_ns":0,"collect_ns":0,"total_ns":0}
```

- `process_ns` 包含对引擎的按键处理/查询更新；`collect_ns` 包含实际生成并复制前十候选及获取预编辑/commit状态。不能把惰性求值放到两者之外。`total_ns` 覆盖这两个阶段，计时止于输出 JSON 序列化之前。
- 计时不含 stdin等待、JSON解析/序列化、stdout与父进程IPC，父进程请求往返另报。
- `candidates` 最多十项，保持引擎原顺序；不得用目标词改变候选或排序。不能取得十项时返回实际数量并在配置披露。
- `raw_input` 是引擎提供的原始编码缓冲，某些API保留已选前缀，适配器可剥去明确的已消费区间，但必须说明边界；不得把拼音预编辑误写为原编码，也不能单凭缓冲非空判断未完成。API无法可靠获取时用 null 并披露，不能伪造。完成状态由commit与composing共同核对。
- `commit` 只包含本次操作产生的文本，不能重复上次提交；composing反映还有未完成输入/暂存状态。
- 不调用引擎学习接口。无法关闭学习的路径应放在质量专用进程，正式性能只打字和reset，并披露隔离边界。

## 测量步骤

1. 固定环境、Release构建、依赖、源码提交、具体数据哈希及许可文本。校验三个已知编码 `nihc`、`kdhv`、`woxlxtykyu`，确认小鹤配置已生效。
2. 冒烟测试 reset、逐键、peek、选择、退格、取消与重复输入，检查JSON协议、状态与计时非负。源码适配器本身可能有缺陷，先核对实际API和代表样例。
3. 所有构建与词库部署结束后才测正式性能，避免自身并行编译污染结果。先预热，多个配置独立驻留，轮次交错；不停止用户程序或清系统缓存。
4. 用固定样例逐键查询并实际枚举十个候选，每条前reset。目标每配置至少约一万次按键；若运行成本过高而减少，明确样本数及原因。记录每轮与场景分桶 p50/p95/p99、最大值、CPU、进程RSS/峰值、负载与失败。
5. 质量pass与正式性能分开，先打完编码再显式选择目标；保存每步响应及最终commit，失败仍保留，不从报告消失。
6. 冷/首次启动只报告真实样例，文件缓存未清空时不能称磁盘冷启动分布；部署/编译耗时不当输入耗时。
7. 禁网复跑核心加载及代表样例，检查运行阶段只用本地材料。进程沙箱不代表未来宿主或全机系统服务已经验收。
8. 汇总可运行项、未完成项与原始证据，同步产品状态。不选择未通过质量/许可门槛的默认底座，不把核心探针称为原生输入法完成。

## 后续边界

本轮先回答哪套中文组合值得接入原生最小闭环。UI、宿主实际收字、焦点切换、同应用换字段、学习模式翻译竞争、用户词学习与更新恢复均需后续独立验证。若生产组合无法按固定版本运行，先记录具体阻塞，不据此宣称该引擎质量差。
