# 扩展词库调研（2026-11-24）

> **实施状态（2026-11-26）**：0.5.0 已发布，本文只作裁决依据与许可红线记录，不再同步实施进度。合同全文见[扩展词库](dictionaries.md)，阶段状态见[实施计划](implementation-plan.md)「扩展词库」表。

用户痛点：出厂词库（libime `dict-20260907` 单本）词语不够全、不够新。本文调研社区输入法的词库生态，记录本机实测数据，给出三层方案与数据源许可红线。裁决已逐条写入第三节；实施排期归[实施计划](implementation-plan.md)，本文是依据。

> **实施状态更新（2026-11-26）**：0.5.0（b131）已于 2026-11-24 发布 stable——D0–D6 全部落地，官方词库渠道 catalog-1 已上架 `gomeen/gogaku-dicts`。本文保留为裁决依据与许可红线记录，实施进度以[扩展词库](dictionaries.md)与[验收记录](validation/dictionaries-0.5.0.md)为准。

本文经过三轮审查。第三轮用本机已编译的 libime 1.1.17 写了独立探针实测（第二节），并更正了前两轮的五处错误说法（第六节）。

## 一、本仓库现状（代码调查）

| 项 | 现状 |
| --- | --- |
| 出厂词库 | `sc.dict`（磁盘 4.3MB，300,471 条字词）＋`zh_CN.lm`（33.1MB），哈希锁定，缓存于 `~/Library/Caches/Gogaku/libime-1.1.17/data/`，不在仓库 |
| 加载点 | `shared/GogakuCore/normal_session.cpp` `gc_normal_session_create`（约 1036-1046 行）只 `dict->load(0, ...)`；学习会话 `learning_session.cpp:43` 同样只有一本 |
| 槽位占用 | 槽位 0 是系统词典；槽位 1（`kUserDictIdx`）放自定义拼音词（权重 +18）和已学词（权重 −12），经 `addWord` 逐词注入 |
| 加载方式 | sc.dict 用 istream 整体读入堆内存，不是 mmap；kenlm 在 macOS／Windows 上没有 `MAP_POPULATE`，同样走 malloc 加整读 |
| 引擎所在进程 | macOS：IMK 进程内一份普通会话（`EngineHub.swift` 单例），学习会话另有一份。Windows：TSF DLL（x86／x64）不加载核心，引擎在每用户 x64 代理 `GogakuAgent.exe`，宿主经命名管道 RPC 调用，截止 400ms（`core_bridge.cpp`） |
| 学习引擎实例 | 只在学习翻译启用且进入学习模式时创建；学习关闭、Lite 构建（stub）和 Lite 模式都不创建。Windows 代理**每个处于学习模式的管道连接各建一份**（`agent.cpp:175-179`） |
| 线程模型 | 共享核心没有线程，也不是线程安全的。macOS 所有 C ABI 调用走串行队列 `org.gogaku.engine`；Windows 代理用 `core.mutex` 串行化 |
| 改动通知 | macOS：设置应用发分布式通知 `org.gogaku.settings.changed`，输入法调 `gc_normal_reload_custom_words`。Windows：设置应用经管道发 `op:"reload"`，代理另有 500ms mtime 轮询兜底，宿主侧 TSF 从 RPC 响应里的 `settingsRevision` 得知变化 |
| 用户数据目录 | stable、dev、完整版、Lite 共用同一目录：macOS `~/Library/Application Support/Gogaku/`，Windows `%LOCALAPPDATA%\Gogaku`（通道只区分管道名和注册表键） |
| 自动读音 | `custom_words.cpp` `build_readings` 把出厂词典导出成文本，按单字取最常用读音，缓存在设置进程里 |
| 设置 | `settings_contract.cpp` 没有词库字段；UI 只有「自定义词语」页 |
| **能力底座** | 本仓库锁定的 libime 1.1.17 已有多词典 API：`addEmptyDict()`／`setTrie(idx)`／`removeFrom(idx)`／`dictSize()`，`PinyinDictFlag::{FullMatch, Disabled}`。扩展词库**不需要改 libime** |

fcitx5 上游用法（`fcitx5-chinese-addons/im/pinyin/pinyin.cpp`）：槽 0 系统词典、槽 1 用户词典，之后是拆字和 extB 两本内置扩展，再往后是 `pinyin/dictionaries/` 目录下每本 `.dict` 一个槽位。目录词库由 worker 线程解析后 `setTrie` 挂载，默认全部参与排序；同名 `.disable` 文件表示停用，做法是不加载。`FullMatch` 只用在拆字词典上。

## 二、本机实测（2026-11-24）

**方法**：用本机已编译的 libime 1.1.17 dylib（与发布包同版本）链接一个独立探针，在 `/tmp` 下运行后删除，仓库代码未改动。测的是 libime 本身，没有经过 Gogaku 的候选合并层（自定义词、英文候选、分页）。机器为 Intel Mac。词库用 fcitx5-pinyin-zhwiki 0.3.1（`zhwiki-20261018.dict`，磁盘 34.2MB，1,734,069 条，其中 98,236 条出厂已有）。

| 项 | 仅出厂词典 | 加挂 zhwiki（全参与） |
| --- | --- | --- |
| 驻留内存 | 约 42MB（sc.dict＋语言模型） | 再增加约 70MB |
| 加载耗时 | — | 约 185ms |
| 逐键 p50／p95／max | 0.90／3.4／6.0ms | 0.90／3.4／6.1ms |
| 单独输入 zhwiki 新词，首选命中（300 词） | 13% | 74%（前 9 位从 22% 升到 97%） |
| 新词在句中（「我想去＋X」，150 句），首选命中 | 11% | 68%；设 FullMatch 时仍是 11% |
| 出厂已有的词，首选命中（300 词） | 66.7% | 67% |
| 30 个常用拼音、12 个英文单词 | — | 首选全部不变；第 2–5 位混入「任敏」「沃门」「我们·异」「慎靓王」等 |

结论：

- FullMatch 只在整段输入恰好是一个词时才出这个词，句中的新词完全用不上。数据支持「默认全参与」。
- 全参与没有改变常用词的首选，副作用是第 2–5 位出现人名、专名噪声。zhwiki 有 164,874 条含间隔号「·」、30,649 条含字母或数字，导入时可以考虑过滤。
- 加挂后逐键耗时不变，但 185ms 的加载如果发生在引擎队列上会卡键（见第三节「加载」）。
- THUOCL 与 zhwiki 互补：出厂词典缺 IT 词表 13,882 条（87%）、法律 9,283 条（94%）、医学 11,983 条（64%），zhwiki 分别只能补上其中 2,060、493、2,664 条。

## 三、已裁决方案

### 第一层：引擎多词典挂载（共享核心）

- **槽位**：每本扩展词库一个独立槽位，从槽位 2 起，不走 `addWord` 逐词注入。启停用 `setFlags(Disabled)`，卸载用 `removeFrom`，逐键路径不改。
- **默认全参与排序**（2026-11-24 裁决，与 fcitx5 目录词库的做法一致）。每本保留 flag 字段，必要时可单本改成 FullMatch。
- **权重**：转换时所有条目权重统一写 0。libime 把词典权重当排序加分，Rime 词频（如 100）原样写入会把正常候选全部挤掉；fcitx5 的 scel 转换同样一律写 0。
- **加载**：后台线程解析成 trie，再回到引擎队列 `setTrie` 挂载，和 fcitx5 一样。原因是共享核心没有线程，macOS 调用走串行引擎队列，Windows 宿主 RPC 截止 400ms，185ms 的同步加载会卡键。C ABI 需要新增异步加载接口；加载完成前打字看不到扩展词。
- **读音兼容**：词库存全拼，libime 编码层自动兼容全拼、八种双拼和模糊音，扩展词库对所有输入方案生效。
- **存储**：`~/Library/Application Support/Gogaku/dictionaries/`（Windows 为 `%LOCALAPPDATA%\Gogaku\dictionaries\`）。每本词库一个 `.dict` 加一个同名元数据文件（id、名称、来源格式、来源链接、许可、版本、条目数、校验和、启用状态），沿用自定义词的原子写入和损坏恢复规范。**不用单一 index.json**：stable、dev、Lite 共用这个目录，两个设置应用可能同时导入，单文件会互相覆盖。
- **内存提示**（2026-11-24 裁决）：设置页每本显示内存估算（实测约为 `.dict` 文件大小的 2 倍），启用合计超过阈值时提醒但不阻止。阈值按实测定。
- **调频**：扩展词库本身不注册调频。普通模式完整上屏的中文按既有语义学入用户词（`learned.txt`＋槽位 1），实现不改。删除扩展词库后，已学入的用户词保留；清空调频时一并清除。
- **删词**：Control＋Backspace 对扩展词候选不删词，提示「扩展词请到设置停用或删除词库」。
- **候选不标识**：与出厂词同观感，不改共享位图渲染器。
- **英文释义**：扩展词没有英文释义注释（gloss.tsv 覆盖不到），UI 如实标注。

### 学习模式只挂小词库（2026-11-24 裁决，替换「同步挂载全部」）

中→英学习的中文来源推导使用 `DecodeCore` 的独立引擎实例。实测每份引擎约 42MB，加挂 zhwiki 后约 112MB；Windows 代理每个处于学习模式的连接各建一份，同步挂载大词库会让内存按应用数成倍增长。

裁决：学习引擎只挂大小在阈值以下的扩展词库，zhwiki 这类大词库只在普通模式生效，不改 Windows 代理架构。挂载逻辑由普通引擎和学习引擎共用同一份实现。阈值按实测定，设置页对未进入学习模式的词库如实标注。

### 第二层：设置页「扩展词库」＋导入转换

- **页面**：列表（名称、条目数、来源、内存估算、开关、删除），「导入」文件选择器，「获取更多词库」入口。非法文件给出具体错误，风格对齐自定义词语页。
- **首批格式**：搜狗 `.scel`、Rime `dict.yaml`、libime `.txt`／`.dict`、无拼音纯词表 `.txt`。两种 `.txt` 按列数和第二列能否解析为拼音区分。百度 `.bdict` 放第二批。
- **Rime 格式**：按 `columns` 字段解析，有些词库没有拼音列（rime-ice 的 `tencent.dict.yaml` 只有 `[text, weight]`）。`import_tables` 清单文件（如 `rime_ice.dict.yaml`）本身没有词条，首批提示用户导入 `cn_dicts/` 下的具体词库，不跟随清单。
- **无拼音词表**（2026-11-24 裁决，替换「不支持无拼音导入」）：共享核心按出厂词库定读音。先查整词；查不到时按出厂词库最长匹配切词，逐段取读音。任何一段（含单字）在出厂词库里有不止一个读音时视为无法确定，丢弃该条并计数报告，不猜测。同一份实现给设置应用导入和发布侧预处理 THUOCL 共用。
- **实现**：转换器在共享 C++ 核心自研一份（scel 是纯数据格式，社区已完整逆向；Rime 和 libime 文本解析成本很低），经版本化 C ABI 供两端设置应用调用，**不并入 GPL-3.0 的深蓝词库转换**。按「一份实现」规则入库两端共跑的测试向量（scel 样例、带／不带拼音列的 yaml 样例、无拼音词表、非法输入）。
- **执行位置**：转换在设置应用后台线程执行，产物为 libime 二进制 `.dict` 加元数据，不经过输入法进程。完成后按既有通知链触发重载（macOS 分布式通知；Windows 管道 `reload`，mtime 轮询兜底）。
- **搜狗**：设置页按钮在浏览器打开 `pinyin.sogou.com/dict`，不抓取站内内容；用户自行下载 `.scel` 后本地导入。

### 第三层：官方精选词库分发

- **机制**：GitHub 仓库清单加 Ed25519 签名，复用[检查更新](update.md)的签名机制。用户在设置页显式点击才下载，校验后安装。已安装词库显示版本，页内「检查更新」按钮手动对比，复用 24 小时节流，只在设置应用打开期间生效，不在后台检查。
- **隐私**：下载请求与检查更新同口径，不携带输入内容、凭据、学习记录或设备唯一标识。
- **首批精选集**：
  - zhwiki 维基百科词条和网络流行语（[fcitx5-pinyin-zhwiki](https://github.com/felixonmars/fcitx5-pinyin-zhwiki)）。仓库代码是 Unlicense，**词库数据遵循 Wikimedia 许可**（CC BY-SA 4.0／GFDL）：分发时署名、注明修改、以相同方式共享。
  - THUOCL 领域词库（[thunlp/THUOCL](https://github.com/thunlp/THUOCL)，MIT，README 声明可用于研究与商业）：IT、财经、法律、医学、饮食、地名等。数据更新于 2016–2017 年；文件首行带 BOM，地名表混有「房地产市场」「市公安局」等非地名条目，发布侧需要清洗。读音用上文同一份无拼音转换实现预构建。
- **萌娘百科**（2026-11-24 裁决）：移出官方分发。词库内容是 CC BY-NC-SA（禁止商用），代码才是 MIT。设置页只给上游发布页链接，用户自行下载 `.dict` 后导入。

### 既有裁决的修订

「自定义词语不导入鼠须管、青简或系统文本替换」**维持不变**，约束对象是自定义词语功能。扩展词库新增独立表述：允许用户自行下载并导入第三方词库文件（含专有格式 scel），本地转换产物只存本机，不提供导出和再分发；官方渠道只分发许可证允许再分发的词库，并逐本署名。

### Gogaku Lite

扩展词库页进入 Lite，侧栏从五页变六页（2026-11-19 五页裁决随之修订），词库数据与完整版共享同一 `dictionaries/` 目录。Lite 没有学习引擎，不涉及学习模式挂载。

## 六、对前两轮说法的更正（第三轮审查）

1. ~~zhwiki 词库是 Unlicense~~：Unlicense 只覆盖仓库代码，生成的词库遵循 Wikimedia 许可（README 原文，Arch 官方包标注 CC-BY-SA-4.0＋GFDL-1.3-or-later）。
2. ~~萌娘百科词库是 MIT~~：MIT 只覆盖 mw2fcitx 代码，词库内容是 CC BY-NC-SA（`pkg-moegirl` 分支 README）。
3. ~~fcitx5 给 zhwiki 设 FullMatch~~：fcitx5 只给拆字词典设 FullMatch，目录词库默认全参与。
4. ~~Rime 词库都带拼音列~~：rime-ice 的腾讯词库只有词和权重。
5. ~~THUOCL 只差读音~~：许可干净，但数据旧（2016–2017），格式需要清洗。

## 七、风险与待验证

- **scel 解析正确性**：依赖逆向格式文档。测试向量要覆盖大词库、多音词和异常样本；解析失败给出具体原因，不静默丢弃。
- **无拼音读音质量**：出厂词库 300,471 条中有 300,035 条权重四舍五入为 0，多读音的段无法靠权重区分，丢弃率可能偏高；最长匹配切错边界时会得到错误读音。丢弃率和错误率要用 THUOCL 和腾讯词库实测，门槛在实施计划里定。
- **候选噪声**：实测全参与不改变常用词首选，但第 2–5 位会混入专名。是否过滤含「·」或字母的条目、是否需要单本降权，用现役输入法测试集验证。
- **合并层**：实测没有经过 Gogaku 的候选合并层（自定义词、英文候选、分页），实施时补测。
- **性能和内存**：逐键 p95 门槛不放宽。异步挂载不得阻塞首击。内存提醒阈值和学习模式挂载阈值按实测定。
- **签名渠道**：词库清单与更新清单是否共用密钥和仓库，在发布脚本阶段决定。
