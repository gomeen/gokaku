# 双端功能统一、安装包与检查更新计划

状态：**已批准并实施中。** Windows 初始范围为只交付最终 Setup.exe、运行交用户；用户完成安装后追加授权在同一 VM 排查输入、候选窗、设置与图标。限定运行证据单独记录，Windows 桌面仍不是本机构包前置。原计划的功能目标和未完成项继续记录，不能把构包或限定宿主通过等同双端功能验收。 本计划取代原单 Mac 阶段计划，覆盖 macOS 与 Windows 的功能一致、安装、升级、卸载与检查更新。产品行为以[产品方向](product.md)为准，功能状态见[双端功能对照](feature-parity.md)，更新合同见[检查更新](update.md)，历史证据见[原生开发验收](validation/native-development.md)。

## 一、目标与范围

交付功能一致的 macOS 与 Windows 开发测试版，覆盖普通输入、双向学习、拼写、设置、自定义词、快捷键、应用偏好、完整皮肤、安装、升级、卸载与检查更新。

| 项 | 本轮范围 |
| --- | --- |
| macOS | 当前 Intel Mac、macOS 26.x；**对外只交付 `.pkg`**，不生成／交付 DMG；内部仍可产生 `.app` 中间产物 |
| Windows | Windows 11 x64；安装包内含 64 位与 32 位 TSF／应用；Windows ARM64、Windows 10 不在范围 |
| 翻译 | **只保留火山 NMT**；移除本地模型、CT2、SentencePiece、PyTorch、后端选择、beam、模型准备与下载入口 |
| 检查更新 | GitHub 公开 Releases＋Ed25519 签名清单；自动检查可选、**默认关闭**；下载与安装始终由用户点击 |
| 签名 | 开发测试包不做 Apple Developer ID／公证或 Windows Authenticode；更新清单签名独立，不混称系统代码签名 |
| 记录采集 | 维持关闭；两端保留相同偏好、查看与管理语义，不借移植解锁 |

「功能一致」指入口、输入规则、设置效果、数据格式和失败行为一致；系统控件、字体栅格化、应用身份和系统拼写词典允许平台差异。

## 二、共享合同

继续使用同一 C++ 核心（当前 ABI v4），Mac 用 IMK／AppKit，Windows 用 TSF／Win32。以下合同独立版本化：

| 合同 | 要求 |
| --- | --- |
| 核心会话／快照 | 会话、焦点代次、组合、修订、模式、方向、源文、候选与消费范围；状态变化有序执行；平台只转换键／文本／修饰键／焦点事实 |
| 提交意图 | 唯一 ID、会话、组合、修订、焦点代次、候选身份、目标与恢复内容；平台重新验证宿主后最多执行一次；结果不明不自动重试；仅确认成功才调频 |
| 翻译请求／结果 | 协议 v1、请求 ID、精确源文、方向、修订、资源标记；火山失败类别稳定；迟到结果不得进入候选；辅助进程无宿主写入权限 |
| 设置 | 版本化 UTF-8；schema 2 移除本地模型后端／beam；旧本地模型配置迁移为关闭云翻译；已启用火山配置保留凭据与用量 |
| 自定义词／调频 | TSV v1 与调频格式两端共用；原子写、损坏备份、删除不复活 |
| 更新清单 | schema 1、keyId、版本、单调构建号、通道、说明、平台／架构／minOS／assetId／大小／SHA-256；原始字节 Ed25519 分离签名 |
| C ABI | 整数／UTF-8／长度；DLL 内申请内存由同一 DLL 释放；破坏性变更两端同步重编译并升 ABI |
| 数据迁移 | 非 ASCII 路径、原子替换、写失败恢复、并发通道合并；不兼容数据版本拒绝写入 |

### 共享范围的划法与重复实现（2026-11-07 复盘）

本节记录一个已发生的事实及其根因。设置迁移、更新清单验签、火山请求签名、主题调色板目前在 Swift 与 C++ 各有一份实现（`Sources/GogakuCore/Settings.swift`、`Sources/GogakuCore/UpdateContract.swift`、`Sources/GogakuCore/Volcengine.swift`、`Sources/GogakuCore/CandidateTheme.swift` 与 `native/GogakuWindows/platform.cpp`、`update.cpp`、`services.cpp`、`themes.cpp`）。两端不会因为改错一端而变红，只能靠注释对照维持：`themes.cpp` 的「Exact semantic palettes from Sources/GogakuCore/CandidateTheme.swift」与 `services.cpp` 的「须与 Swift 逐字节一致」就是这种状态的自述。

根因不是某一条规则要求写两遍，而是三条规则叠加后让写两遍成为合法且最省事的路径。

1. 共享范围只划到输入会话。`docs/product.md` 规定「业务核心迁移为共享 C++ 实现」并把 Windows 端描述为「以 C++／Windows SDK 实现 TSF 文本服务和 Win32 界面」，没有把设置、更新、主题、翻译凭据这些非会话逻辑划进共享范围。
2. 一致性只要求可观察行为与格式，不要求单一实现。上文「功能一致」的定义是入口、规则、效果、格式和失败行为一致，两份实现只要行为对齐就算合规。
3. C ABI 只覆盖会话，非会话合同没有落点。`native/GogakuCore/include/gogaku_core.h` 导出的 30 个函数全部是 `gc_normal_*` 与 `gc_learning_*`，设置、清单验签、请求签名、主题数据都没有共享入口，Windows 侧要复用只能自己写一份。
4. 验收按端列状态，完成判据是「已编译」。`docs/feature-parity.md` 每行一列一端，P3 的完成条件是编译通过，于是照 Swift 再写一遍 C++ 是达成验收的最短路径。
5. 没有对拍检查。两端测试各测各的，没有一组共享输入与期望结论同时约束两边，所以漂移不可见。

因此补的不该是又一条「不要重复」的禁令，而是缺的两个东西：共享层给非会话合同留入口，以及能把漂移变成红色的对拍向量。

### 共享实现规则（约束后续改动）

- 解析、规范化、迁移、签名、校验、内置数据表这类与 UI 和系统 API 无关的逻辑只有一份实现，住在共享核心。平台侧只转换按键、文本、路径、应用身份和系统控件。
- 确需第二份实现（例如平台系统 API 没有替代品）时，必须入库同一组输入与期望结论，并让两端测试跑同一份数据。没有对拍向量的第二份实现不得合入。
- 跨端一致不允许以注释对照、逐字节人工核对或「照某文件写」作为维持手段。已存在的重复实现按此规则登记，随契约抽取逐个消除。
- 平台允许的差异只有系统控件、字体栅格化、应用身份与系统拼写词典。

### 契约抽取顺序（第 1、2 行已完成；第 3、4 行经裁决不执行）

目标是把上表里已存在两份实现的高频契约搬到共享核心，共享层的 C ABI 新增一组 `gc_contract_*` 入口：入参为字节或 JSON，出参为状态码加规范化 JSON，内存仍由库内申请库内释放。数据形状先定，顺序按「无加密 −> 有加密」排：

| 顺序 | 契约 | 共享实现要拿到的数据 | 两端剩余职责 | 验证 |
| --- | --- | --- | --- | --- |
| 1 | 设置解析／迁移／规范化 | `settings.json` 原始字节，输出 schema 2 规范 JSON 与迁移事件 | Mac 把规范 JSON 解成 `Settings`；Windows 同样；两端不再自己判版本与迁移 | 同一组向量在 Swift XCTest 与 Windows selfcheck 各自跑一遍，结论逐条相同 |
| 2 | 内置主题与调色板 | 主题标识，输出调色板与排版数据 | 渲染、字体回退与图片解码由平台自己做 | 去掉 `themes.cpp` 的内置表后，两端取到的 JSON 逐字段相等 |
| 3（不执行） | 更新清单验签 | 清单原始字节、签名、公钥、当前通道与构建号、平台与架构 | 下载、缓存、UI 状态机留在平台 | 同一组篡改样本两端得出相同的拒绝原因 |
| 4（不执行） | 火山请求签名 | 方法、主机、路径、查询、请求体、密钥与时间戳 | 传输、超时、取消与计量留在平台 | 与已入库的固定向量逐字节相等 |

前置动作：先入库一组两端共跑的对拍向量（同一份输入与期望结论），再动第一行。没有向量的抽取不开始。当前端内两份实现（`Sources/GogakuCore/UpdateContract.swift` 与 `native/GogakuWindows/update.cpp` 等）保持原状，不在此轮一边抽取一边加特性。

**进度（2026-11-07）**：第 1 行与第 2 行已落地。第 1 行（设置读侧规范化）见上节；**Windows 已接线（编译验证）**，VM 运行重验待做。第 2 行（内置主题）：`theme_contract.cpp` 经 `gc_themes_builtin` 输出四套主题的规范 JSON，Mac `BuiltinCandidateThemes` 与 Windows `themes.cpp` 都改为消费契约，两端硬编码调色板表与「Exact semantic palettes」式注释对照已删除；向量冻结锚点色（含产品规格 #12996a），并入两端 ctest 与 Windows 自检包。主题包容器（ZIP／PNG／WIC）仍在两端各算一层，属后续。**第 3、4 行（清单验签、火山签名）经用户裁决不执行（2026-11-07）**：不把 monocypher 上移共享核心，Mac 保留 CryptoKit、Windows 保留 monocypher＋CNG，两端各自实现维持原状。这两处因此是「共享实现规则」的已登记例外——将来任何一端改动清单验签或请求签名前，必须先入库两端共跑的对拍向量，否则不得合入。

已知缺口（未修，不阻塞）：规范化只发生读侧，迁移结果不会主动写回磁盘。旧 schema 1 文件在 Mac 上读到的是「学习翻译关闭」，但文件本身仍是 schema 1；由于合并写盘只写差异字段，它可能长期不动。降到旧版本阅读同一文件时会看成开启。处理方向是让设置应用在读到 `migrated=1` 时做一次规范写盘，按写侧迁移单独验收，不在读契约里做副作用。

设计上的两个取舍：出厂默认值只看两端语义相同的字段，按应用默认英文的应用清单由平台在空列表上自行补（平台身份允许差异）；未来版本（`schemaVersion` > 2）按已知字段读取并输出 2，未知字段原样保留，避免降级时丢数据。

### 学习提交协调

计划将 Mac 控制器中剩余的学习提交协调抽为共享模块，统一预译缓存、等待期间按键缓冲、失败恢复、取消、焦点代次及一次提交规则。**当前状态：预译缓存、翻译调度合同与一次提交在共享核心／薄封装；等待期间按键缓冲仍在 Mac `InputController`，Windows 尚无对应实现。** 这是 P1 的剩余项，不作为已完成宣称。

## 四、Windows 集成

- 提供 x86／x64 两套薄 TSF DLL，由每用户 x64 代理加载共享核心并持有输入会话。TSF 处理按键、字段身份、编辑会话、宿主提交及非激活候选窗；代理集中协调调频持久化、设置与翻译统计。
- 使用 Windows SDK 真实 COM 接口与常量；准确传播注册、启用和提交失败；重新验证条目消失问题，不沿用未经证实的旧归因。
- 命名管道限定本机与当前用户，版本化、限长消息及独立会话身份；隔离组合、草稿和响应。
- 启动及握手完成前不消费输入；代理失联不吞键。普通按键不等待 HTTP、拼写或写盘；IPC 计入逐键性能预算。
- 请求有明确超时和撤销机制；迟到响应不写宿主。AppContainer、不同完整性级别及多用户登录单独验收；不放宽程序目录权限解决兼容。
- 持久化支持 Unicode 路径、句柄刷新及原子替换；Windows 使用 `MoveFileEx`＋`FlushFileBuffers` 语义，移除「先删除再 rename」「fsync 空操作」临时补丁。
- 设置应用为简单 Win32，不进按键性能链；安装器为 Inno Setup，程序与只读资源进 Program Files，用户数据放 `%LOCALAPPDATA%\Gogaku`；UAC 只做机器级注册，启用与用户配置以原用户身份执行。

## 五、功能与配置

### 普通输入

小鹤／全拼、九组模糊音、英文候选与释义、输入字母显示、调频及清空、按应用默认英文、自定义词、快捷键、完整皮肤。行为规格以[产品方向](product.md)「普通模式行为规格」为准；本轮不重新设计输入规则。

### 火山翻译

- 以独立辅助进程运行；Mac 随包 `GogakuTranslator --volcengine`，Windows 由代理派发；不依赖用户 Python、Xcode、VS 或 pip。
- 设置提供学习翻译开关（默认关闭）、Access Key ID／Secret Access Key 保存与移除、用户点击的连接测试、未配置／已配置／最近失败状态。
- 凭据独立存储、仅当前用户可读；不进设置导出、主题包、日志或安装包；更换凭据后废止旧进程状态。
- 本机统计标为「本机本月请求字符统计」，不宣称账户余额；成功响应优先使用服务计量，预译计入、缓存命中不重复；失败不无限重试。
- 两方向统一处理断网、超时、认证／权限、限流、余额、空结果、服务错误：提示并恢复可编辑源文及有序缓冲，不自动上屏或切换语言。Esc 取消；切字段／应用使旧请求失效；未完成内容只可显式恢复为新组合。
- 原文上屏保留 Mac Command+Enter、Windows Ctrl+Enter，仅活动学习组合消费。

### 设置、皮肤与拼写

Windows 完整覆盖七页：学习翻译／资源、普通输入、皮肤、自定义词语、快捷键、学习与隐私、学习片段；更新入口放在版本信息旁，打开独立更新窗口。

- 普通输入：小鹤／全拼、九组模糊音、英文候选与释义、输入字母显示、调频及清空、按应用默认英文。
- 自定义词：短码／拼音词、自动读音、启停、搜索、排序、校验与失败重试，共用 TSV 格式。
- 快捷键：录制、禁用、恢复和冲突检查；保留现有两个可配置命令，不恢复快速添加。
- 模式及方向遵循全局偏好，不恢复按应用学习模式记忆；应用默认英文使用平台应用身份，Windows 支持程序路径及包身份。
- 皮肤：四套内置主题、统一选择、主题内单／双色、草稿保存与应用分离、九条固定预览、字体、布局、透明度、背景图、`.gogakutheme` v1 导入导出。Windows 使用 DirectWrite／Direct2D、WIC 与随包 WebP 解码；缺字体回退系统字体。
- 拼写：Windows Spell Checking API，后台执行；资源缺失显示不可用。只标记用户英语，支持免标记、忽略词与点击解释，不自动纠正。

## 六、检查更新

完整合同见[检查更新](update.md)。要点：

- 两端版本信息旁「检查更新」；更新窗口显示当前版本／构建号、新版信息、发布说明、下载进度及错误，并提供「自动检查更新」开关。
- 手动检查始终可用；区分已是最新、发现新版、当前系统不支持、无法连接、更新配置缺失和校验失败。
- 自动检查默认关闭；开启后在设置应用启动及运行期间按 24 小时间隔检查；关闭设置后不另起常驻进程，不在输入按键路径检查。自动检查每天最多尝试一次；手动检查可立即重试。
- 自动发现新版只在设置应用内提示，不抢焦点、不自动下载／安装／重启。下载可取消、重试；校验成功后才出现「安装更新」；点击后打开系统安装器。
- 请求不携带输入内容、火山凭据、学习记录或设备唯一标识；开关旁说明会连接 GitHub。
- 发布使用 GitHub Releases；每个 Release 附清单与 Ed25519 签名；先上传资产取得 ID，再生成清单、上传清单与签名，先形成 Draft，人工审阅后发布。stable／dev 互不自动切换；stable 只接受正式版本，dev 可接受 dev／rc；按构建号判断，不自动降级。
- 未配置更新源的构建明确显示「未配置更新源」，不能显示「已是最新」。

## 七、安装、恢复与发布

### macOS：仅 PKG

产物为 `Gogaku-<version>-b<build>[-dev].pkg`，保留当前用户级安装位置和手动启用输入源语义。

- 构建与交付流程不再生成 DMG 或提供 DMG 指引。
- 安装前完整解包并检查双 App（身份、构建号、签名），备份旧输入法和设置应用，再替换；任一步失败恢复两者，不先删除唯一可用副本。身份与签名在打包阶段完成，postinstall 不重签；Developer ID 签名／公证流水线已备，缺证书时明确失败。
- 事务状态写入用户目录；中断后下次安装或 `manage-install recover` 先恢复；安装失败不提示成功。
- 验证重新注册与实际安装构建号；不能假定切换一次输入源必然替换旧进程。不强杀宿主、不擅自注销或重启；必要时提示重开设置、切换输入源或注销。
- 升级保留设置、词表、主题、凭据和数据。安装器不自行联网，不在安装脚本中执行更新检查。

### Windows：完整 Setup.exe

产物为 `Gogaku-<version>-b<build>[-dev]-windows-x64-setup.exe`，包含双位数 TSF、x64 用户代理与核心依赖、设置、普通输入资源、许可与构建清单。

- Inno Setup 可在 Windows 构建机，或本轮已打通的 Mac＋Wine 上运行编译器生成；程序与只读资源安装到受保护的 Program Files，用户数据放 `%LOCALAPPDATA%\Gogaku`。
- UAC 完成机器级注册，启用和用户配置以原用户身份执行，不误写管理员账户。
- 只增加 Gogaku，不修改默认输入法、系统显示语言或其他输入源。
- 使用版本化程序目录，避免直接覆盖宿主锁定的 TSF DLL；保留上一版本恢复，旧宿主释放后再清理。
- 不强杀宿主或自动重启。需要重开应用、注销或重启时明确提示。
- 卸载对称撤销本通道注册，默认保留数据；共用数据清理为独立显式操作。

### 发布合同

`version.json` 继续作为唯一版本来源；对外提供包前递增构建号，rc／定版要求干净工作区。输出包哈希、来源提交、平台／ABI／协议版本、依赖与验证报告。公开 Releases 分发纳入交付链；公开发布前完成随包声明、适用源码及替换／重链接说明、衍生数据许可和 Gogaku 自身分发许可决定。发布脚本对缺失配置、许可材料或验证证据明确失败，不制作看似可更新的假发布。

## 八、测试与验收

- **共同逻辑**：两端运行相同普通输入、候选消费、Unicode、分页、提交确认、撤销及学习会话向量；验证并发调频、自定义词更新、双通道共用数据，防止丢失更新或已删内容复活。
- **迁移与设置**：本地模型旧配置、已有火山配置、新安装、损坏文件、非 ASCII 路径、写盘失败及重试；自动更新偏好保存后重开一致。
- **翻译**：受控成功与错误响应，覆盖等待时继续输入、Esc、切字段／方向／输入源、重复及迟到响应、重试和原文上屏；成功只提交一次，失败保留输入，普通模式零翻译请求。再用授权凭据少量实测签名、TLS、计量和双方向。
- **主题与拼写**：主题包往返、单／双色、缺字体、图片与透明度、固定预览、非法／超限 ZIP；系统词典缺失、免标记、忽略词、修订后旧诊断失效。
- **更新逻辑**：新版／同版／更高构建号／旧版、dev／rc／stable 隔离、不支持架构与系统、分页、限流、离线、超时、未知 schema、无签名或错误签名、哈希与大小不符、取消和磁盘不足。默认不自动联网，开关关闭后取消待检查，手动重试可用。
- **更新安装**：测试签名清单和受控 HTTPS 服务完成协议回归；首发配置后以真实 GitHub Releases 验证获取、下载和校验。两端均用两个构建验证旧版发现新版、安装、重开显示新版本、保留数据及失败恢复。未完成真实链路前不标记在线更新已验收。
- **Windows**：干净 Windows 11 x64 VM，管理员与标准用户发起安装；记事本、Chrome、Windows Terminal、Electron、x86 测试宿主及真实 32 位应用。覆盖多字段、密码／受限上下文、候选不抢焦点、多屏 DPI、代理崩溃、注销重登、重启、双通道、卸载重装和锁定 DLL 升级。
- **Mac**：回归当前普通输入、主题、设置、翻译失败行为及 PKG 新装／升级／恢复；安装后检查真实运行构建，不能只看磁盘文件。
- **节奏与门槛**：日常 `verify.py --profile fast`；共享核心及内存敏感路径加 ASan／UBSan quick。交付前按仓库要求后台运行 release 全量，真实按键测试安排在用户空闲时。逐键 UI 线程 p95≤5ms、热态候选 p95≤30ms／p99≤50ms、就绪提交 p95≤30ms；Windows 包括 IPC。已有 Mac 性能阻塞须复验；云翻译延迟按真实网络条件报告。

## 九、交付与默认值

交付 Mac PKG、Windows Setup.exe、双端功能对照表、更新与发布脚本、签名清单合同、构建身份及哈希、安装／升级／恢复／卸载说明、验证报告和朋友真机验收清单。

明确默认：

- 自动检查关闭；开启后仅设置应用运行时每天最多检查一次；不自动下载或安装；更新通道跟随安装通道；不自动降级。
- 学习翻译默认关闭；未配置火山凭据不发送；普通输入离线。
- 源码公开与否不由发布仓库决定；第三方许可义务不省略。
- 在线主题商店、学习记录采集解锁、更多架构及平台代码签名不在本轮范围。

实际验证与发布时所需外部输入：测试火山凭据、Mac 空闲测试时段、朋友真机结果，以及 GitHub 发布仓库／权限和发布签名环境。分别记录「可构建、可安装、功能验证、在线更新验证、正式验收」，不把开发测试包或局部证据表述为完整正式产品通过。
