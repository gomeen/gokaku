# 首阶段实施总计划（macOS＋Windows 双端）

状态：**双端首阶段计划已批准，本计划替换原单 Mac 实施范围；Windows 环境未就绪，完整双端未通过。** 已有 Mac 原生工程与限定场景验证保留为历史证据，见[实施验收记录](validation/native-development.md)；历史实测不倒改。

## 一、目标、当前状态与结论

同时交付**当前 Intel Mac／macOS 26.7.2** 和 **Windows 11 x64** 的本地开发版，包含普通小鹤输入、中英双向学习、词／短语／整句候选、拼写提示、30 天本地学习片段和安装恢复。

当前 Mac 已有原生工程及限定场景验证，不重新从零实现。但现有 `GogakuCore` 混有 AppKit、Darwin、Mac 路径和系统通知，组合／学习状态主要在 Swift 中；不符合双端共同交付的复用目标，必须调整。

**保留 libime 和原生前端路线，迁移共享业务核心到 C++，两端通过同一版本化 C ABI 使用；Windows 新增 TSF 前端。两端统一模型，不再以 Apple Translation 作为正式后端。** 不为跨平台引入 Flutter、Electron 或通用插件平台。

当前没有 Windows 环境。环境准备是明确前置条件：未获得 Windows 构建和可操作桌面之前，不得将 Windows 或双端交付标为通过。

## 二、架构决定

### 共享 C++ 核心

将现有 Swift 中的以下规则逐步迁入同一个 C++ 实现：

- libime 调用、小鹤解析、分页、部分选择与源范围消费。
- 组合状态、修订、候选身份、模式／方向、草稿、确认与取消规则。
- 翻译请求调度、缓存、超时、失效结果拒绝和提交去重。
- 拼写问题的数据结构、学习事件分类、记录保留／删除与 SQLite 存储规则。
- 平台无关设置、主题标识与资源清单。

共享核心不得包含 IMK／TSF 对象、窗口、系统键码、NSEvent 位标志、Apple 路径或宿主插字操作。平台输入先转换为统一的键、文本、修饰键与焦点事件，核心只返回状态和意图。

沿用 libime 1.1.17 固定提交及已核查数据来源。其上游已有 Windows Clang64 构建／测试工作流，但这只证明存在构建路线，不能代替 Gogaku 自己的验证。

### 两端原生宿主与界面

- **macOS**：保留 Swift、InputMethodKit、AppKit 及现有面板／设置界面；改为共享核心的调用方。现有宿主兼容处理留在 Mac 实现内，包括确认提交时确有必要的协议处理，不混入共享规则。
- **Windows**：以 C++／Windows SDK 实现 TSF 文本服务、焦点验证、编辑会话、按键路由与插字；Win32 非激活候选面板，简单 Win32 设置应用。设置不位于按键性能链，不引入额外管理框架。
- 两端都使用光标旁浮动预编辑：未确认内容不写入宿主、不另开编辑器；只有明确确认才执行当前宿主提交。
- 拼写分别接 NSSpellChecker 和 Windows Spell Checking API；共享诊断数据合同与测试规则，不要求两套系统词典逐词完全相同。英语检查资源缺失时明确报告，不能默认为检查通过。

### 统一接口与所有权

| 接口 | 合同 |
| --- | --- |
| 核心会话命令／快照 | 会话、焦点代次、组合、修订、模式、方向、源文、候选及消费范围；所有状态变化有序执行 |
| 候选快照 | 稳定 ID、中文来源、源范围、目标、说明、资源版本与就绪状态；已显示编号不被迟到结果替换 |
| 提交意图 | 唯一 ID、对应候选及修订、目标文本和恢复内容；平台重新验证宿主后最多执行一次，结果不明不自动重试 |
| 平台宿主事实 | 不透明焦点标识、应用标识、安全状态及必要选区信息；不把原生对象或宿主正文交给共享核心 |
| 翻译请求／结果 | 版本、请求 ID、精确源文、语向、修订和资源版本；结果无插字权限 |

C ABI 使用明确的整数、UTF-8 及长度；DLL 内部申请的内存由同一 DLL 释放，异常、STL 对象和 C++ 运行时对象不得跨 ABI。Windows 补齐 DLL 导出、ABI 版本检查及 UTF-8 文件路径处理。原始小鹤偏移、Unicode 标量和 UTF-16 范围分别定义，不混用。

## 三、构建、运行与数据

- 共享核心使用 CMake／Ninja：Mac 使用 AppleClang；Windows libime 依赖沿用上游 MSYS2／Clang64 路线。
- Windows TSF 及设置程序使用 MSVC／Windows SDK，通过版本化 C ABI 加载共享 DLL；不跨编译器传递 C++ 类型，增加 MSVC 调用 Clang64 DLL 的独立烟测。加载路径仅限安装目录，不依赖系统 PATH 或 MSYS 环境。
- Mac 继续用 SwiftPM 构建前端与测试；现有包不再要求共享核心包含 AppKit。动态库闭包分别打包为 dylib／DLL。
- 两端统一资源逻辑版本和词库来源；语言模型二进制先验证格式兼容，不直接假设 Mac 生成的 KenLM 文件能在 Windows 使用。必要时从相同固定源数据生成各平台产物并分别记录哈希。
- 用户数据分别放 Mac 的 Application Support 和 Windows 的 LocalAppData。不得把任何一个平台的路径放入共享业务模型。
- 设置迁移到带版本的 UTF-8 结构，快捷键使用规范修饰键而非 NSEvent 原始位；保留现有 Mac 偏好。学习记录保持相同语义，迁移时正确处理旧 Swift 日期编码，不丢弃旧数据或把合成记录当真实学习证据。
- 中文调频默认开启（只学习普通模式完整上屏的中文，本地存储，设置可关与清空），不导入其他输入法个人词库。自定义词语存 `~/Library/Application Support/Gogaku/custom-words.tsv`（带版本行、制表符分隔、原子写入），格式两端共用；规格见[产品方向](product.md)「已确认的自定义词语」。项目公开许可仍不在本次本地开发版交付中决定，第三方实际义务仍须履行。

## 四、两端统一翻译模型

### 正式路线与停止条件

- Apple Translation 退出正式交付链路；已有探针保留为历史证据，设置页不再把安装 Apple 语言资源作为学习功能前置。
- 本轮唯一模型候选为已核查的 `alirezamsh/small100`，固定 revision `8ab680e26a596d2e3d2d2d17ae0f68df1037328c`。
- 两端采用相同 CT2 INT8 产物、分词实现、词表、语言标记和 greedy 参数；初始 batch=1、2 线程。正确使用 small100 的目标语言输入前缀，不照搬 M2M100 协议。
- 模型转换使用隔离环境；生产翻译辅助进程采用 CTranslate2 和 SentencePiece 的本地实现，Windows 按其支持的 MSVC 工具链构建，避免把 PyTorch／转换环境装入输入法进程。
- 使用同一权重不保证不同 CPU 后端逐字输出完全一致：分别运行同一验收集，比较差异并审阅语义；不通过强制回退或隐藏差异制造一致。
- **small100 任一端质量、离线能力或性能不合格，双端学习交付保持阻塞。** 不改为一端 Apple、一端其他模型，不恢复 OPUS／M2M100，不自行扩模型名单。

### 词与表达资源

采用审核后的 CC-CEDICT 义项及 Tatoeba 直接中英句对，保留逐条来源、许可和修改信息。只将可直接发送、已经审阅的表达暴露为候选；不倒置释义充当反向词典，不打包权利链未核清的 ECDICT。未命中可以走通过验收的统一模型，覆盖失败仍计入验收，不围绕测试集临时补表美化结果。

### 调度与进程

共享规则保持一个执行中任务＋一个最新待办、120ms 防抖、64KiB 消息上限、512 个 Unicode 标量及模型 token 上限、10 秒超时。精确词典命中不等待防抖；缓存仅内存、≤1MiB、5 分钟过期。

Mac 输入源使用一个隔离翻译进程；Windows 多个宿主中的 TSF 实例共用每用户翻译代理，避免每个应用加载一份模型。Windows 本地 IPC 只允许当前用户、拒绝远程访问；Mac 和 Windows 使用同一版本化请求协议，平台只适配进程启动与传输。代理无宿主写入权限，旧请求即使仍在计算也不能恢复提交资格。

## 五、统一行为与必要平台差异

保留已确认的产品行为，不因迁移改变输入习惯。普通模式完整行为规格（候选窗、标点、Shift、大写、数字、编辑键、英文候选、按应用默认英文、调频与删词）以[产品方向](product.md)「普通模式行为规格」表为准（2026-10-31 六轮输入习惯原型裁决）；要点：

- 每页 9 个候选（对齐用户青简配置与原型裁决；早前“以计划为准统一为 5 个”的方向已更正）。普通模式数字 1–9 选择，0 或超出先上屏高亮候选再输出数字；学习模式数字保留源文，Mac Option／Windows Alt＋1–9 选择。方向键和 Page Up／Down 导航；`,`／`.` 仅在已有候选时用于翻页。
- 普通模式空格选当前中文、Enter 提交原编码；组合中标点与高亮候选（完整覆盖）或暂存文字＋剩余编码（部分覆盖）一次上屏；组合中 Shift 上屏原编码不切英文，未组合单击切中英；大写字母进入组合作为原样字母。
- 标点表、引号交替与数字后半角例外、拼音光标与 Control＋a/e/b/f/n/p、Home／End 编辑键、英文候选合并排序、按应用默认英文与临时英文、本地调频与 Control＋Backspace 删词均按规格实现；输入区默认用 marked text 显示输入字母（可关）。
- 自定义词语（短码短语与拼音词）属于普通模式核心逻辑，迁入共享 C++ 实现并通过同一 ABI 暴露；存储与校验规格见[产品方向](product.md)。
- 当前未提交内容直接支持整句，选择一次提交；部分选择只消费相应范围，不改已提交正文。未就绪时确认只提示处理中，不预约未来自动提交。
- Esc 取消；按应用默认英文应用中无组合时回到该应用默认。Mac Command＋Enter／Windows Ctrl＋Enter 在活动学习组合中明确原文上屏；无组合时交还宿主。
- 默认 Control＋Shift＋K 切模式、Control＋Shift＋J 切方向、Control＋Shift＋A 快速添加拼音词，菜单和设置提供等价入口；Windows 系统或宿主冲突时通过设置修改，不接管系统输入源快捷键。
- 失焦立即撤销旧提交资格；草稿只在内存保留，明确手动恢复成新组合，不静默覆盖、不跨字段自动恢复。进程退出后草稿不保留。
- 只检查用户英语；点击波浪线只解释，不自动纠正。首版不启用语法检查。疑似错拼只在审核过的容错表达命中时提供对应可提交目标，否则保留原文及提示。
- 默认仅记录成功提交的学习源表达、目标、方向、来源及疑似问题，本地 30 天；不读取宿主周边正文，不记录普通输入、预取、取消或未采用项。
- 暂停、删除、应用排除同时作用于待写队列；SQLite 写入异步且队列≤256，故障不拖慢输入，记录不复活。安全或不确定路径不辅助、不记录，日志不含输入文本。

## 六、实施阶段与前置门槛

### G0：Windows 环境与统一模型可行性

- 用户提供可操作的 Windows 11 x64 桌面环境；实体机或明确标注的虚拟机均可做功能验收，性能按实际环境记录。Windows CI 只承担构建／核心回归，不替代桌面输入验证。
- 先在 Mac 验证 small100 分词、转换、基本质量与速度；同时建立 Gogaku 自己的 Windows libime／C ABI 构建和小鹤烟测。
- Windows 环境未就绪时，只做 Mac 模型门槛和最小共享接口测试，不先大规模迁移所有业务或宣称双端闭环成立。
- Mac 模型已失败则立即停止完整学习分支；Windows 依赖构建失败则记录具体阻塞，不以“上游有 Windows 工作流”当作通过。

### G1：共享核心迁移，保住现有 Mac 能力

- 为当前组合、部分选择、分页、候选冻结、迟到结果、取消、草稿和记录规则建立共同事件轨迹。
- 逐模块迁移到 C++，Mac Swift 层改为薄调用。以现有 Mac 回归和真实限定场景对照，不在迁移中顺便重做面板或设置风格。
- 同一测试向量在 Mac 和 Windows 构建运行；通过后删除旧 Swift 业务实现，不长期维护两套状态机。
- 将 AppKit／Darwin／路径／系统通知／拼写和宿主处理移入各平台实现，不建立无消费者的通用插件平台。

### G2：双端普通输入闭环

- Mac 复验现有 IMK 路径，包括已验证的分页和宿主提交兼容行为。
- Windows 实现 TSF 注册、激活、焦点／编辑会话、非激活候选窗、按键与一次提交；焦点无效时拒绝提交，不用全局注入按键代替 TSF。
- Mac 覆盖 TextEdit、Chrome 和 Terminal；Windows 覆盖记事本、Chrome、Windows Terminal 及一个 Electron 宿主，检查最终文本、选区、焦点和候选身份。
- 输入修订、选区或字段变化后旧候选不能提交。无法验证安全的宿主路径记不支持或阻塞，不仅凭进程或应用名认定相同字段。

### G3：统一模型、学习交互与拼写

- 在两端接入同一模型和词／表达包，支持词、短语和整句；接入各自系统拼写实现，保持同一诊断数据合同。
- 测试原文修改、切方向／字段、候选确认与结果同时到达、重复响应、取消后成功、双击等交错。
- 模型质量和资源许可未通过之前，生产学习候选及真实学习记录继续关闭；测试材料只用于机制测试。

### G4：记录、设置、安装和最终验收

- 共享 SQLite 保留、删除及来源规则；平台设置页只负责显示和操作，不复制业务判断。
- 完成暂停、应用排除、忽略词、片段查看／误报排除／删除、资源安装及快捷键配置。
- 两端提供显式安装、恢复和卸载。Mac 安装当前用户目录、用户手动启用；Windows TSF 注册若需管理员权限，由安装入口明确说明并由用户授权，不自动提权或降低系统安全设置。
- 保留已有输入源，不自动更改默认，不擅自注销／重启。卸载默认保留学习数据，显式清理另行确认。本次不做公开分发、公证或自动更新服务。

## 七、验收标准

### 功能、安全与兼容

- 共用核心测试覆盖小鹤、非首项、部分选择、消费范围、分页、Unicode、英语空格／数字／标点、快照过期与提交去重。
- 真实宿主覆盖三种输入状态、同应用多字段／窗口、选区替换、切模式／方向／输入源、点击说明、快捷键、睡眠唤醒、崩溃、缺资源、安全字段及离线。
- 普通输入不依赖翻译和存储；定义用例内不得丢字、重复、串宿主或静默改写。不同 OS 的焦点判定和提交协议分别验收，不能复用 Mac 通过状态。
- 实测 DLL／dylib 依赖闭包、中文用户目录、非 ASCII 资源路径和升级迁移；缺设备的显示／多屏项目明确列未测，不假称支持。

### 模型质量

复用 32 条风险回归，另在查看输出前冻结每方向 100 条保留集，标注应译／应保留场景。两端分别达到：应译可用率≥95%，固定关键风险没有未处置的意义破坏进入默认候选；空输出、重复及超时计失败。记录平台间输出差异，由用户审阅盲测、参考及分歧并最终确认。

### 性能

两端分别测量，不以共享模型、Mac 成绩或虚拟化环境推出另一台机器的表现：

| 路径 | 门槛 |
| --- | --- |
| 每键宿主／UI 线程处理与准备 | p95≤5ms |
| 热态普通输入→候选可见 | p95≤30ms、p99≤50ms |
| 就绪候选确认→宿主显示 | p95≤30ms |
| 精确词／表达命中→候选可用 | p95≤30ms |
| 热态短表达翻译 | p95≤500ms |
| 20 个汉字以内或对应英语短句 | p95≤2 秒 |
| 冷启动／更长输入 | 单列分布；10 秒超时保留输入，不冒充热态达标 |

比较普通输入、模型驻留空闲和真实双向翻译并发，要求并发时仍满足输入预算。里程碑使用多轮、约万次逐键事件；小改只跑相关回归。保存 CPU／负载／内存、排队与取消后计算，失败和离群值不删除；不把布局返回当屏幕显示，也不无限重测挑成绩。

## 八、完成与停止规则

只有**两端**普通输入安全、共享模型与资源、学习交互、隐私记录、安装恢复和用户语言质量确认全部有证据，才宣布双端首阶段完成。

没有 Windows 环境、任一端模型不合格、核心移植阻塞或真实宿主安全失败，均明确保持对应门槛未通过。可报告已经完成的 Mac 或共享核心里程碑，但不改称双端产品完成；不自行改回不同平台不同模型，也不扩大平台或模型名单。

## 九、执行授权与当前状态
